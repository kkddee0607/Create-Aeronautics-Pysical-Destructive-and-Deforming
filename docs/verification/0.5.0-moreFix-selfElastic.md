# 0.5.0-moreFix — self-only elastic damage retention

## Change scope (user-requested exception to IDS 1.0.7 §7.4/§24.1)

Baseline: `PDD-0.5.0-moreFix-k0.1-FULL-SOURCE-APPLY.zip`. No F/Q propagation, parent/child attenuation, source credit, persistence schema, world-write, or Minecraft/Sable API changed.

Before: the block's own E is applied once to local Q, using transmission `T(E)=.15+.85*(1-E)^1.5` (`E` normalized to 0..1), then direct Q is converted into damage.

New: the extra reduction is applied **only to the block's final raw direct-damage increment**, after local Q has already been attenuated and hardness/damageGain applied. Final self-damage retention relative to E=0 is `R(E)=min(T(E),1-.90E)`. The code applies **only** the ratio `R(E)/T(E)` to `rawDamage`, so Q/activeQ/absorbedQ/directQ/plasticQ/stressQ and the F/Q trace are unchanged; no extra damage is sent to parents or children. At E=100, `T=.15`, `R=.10`, extra damage-only multiplier `2/3`. At E=0, all ratios are 1. Existing stronger damping at intermediate E is retained. Final fixed-point increment (scale 256), projected damage, T1024 break threshold use the revised rawDamage.

This is an intentional revision of the integrated design's historical constraint against multiplying direct damage by another E factor; it does **not** apply E twice to the Q ledger or to F propagation. Existing `DamageModel.Settings` constructor and default values are preserved.

1. Two identical World blocks / prior states, elasticity 0 vs 100, same approved Q and hardness. Expect the E=100 block's **incremental rawDamage** to be 10% of E=0, allowing fixed-point remainder rounding; damage build-up and break threshold follow this value. Note profiles may have different thresholds; use matched material profile overrides if possible.
2. Repeat a collision while monitoring `[PDD-F-SPREAD]`, `[PDD-MATERIAL-TARGET]`, `[PDD-COMMIT]`. For a fixed verified contact and force input, parent/child F/Q, local `activeQ`, `directQ`, `plasticQ`, `stressQ` should be unchanged relative to k=0.1 moreFix; only `rawDamage`, `fixedIncrement`, planned damage / break timing may decrease for high E. Any difference in F/Q is a regression; capture those logs and the profile's E/H/T.
