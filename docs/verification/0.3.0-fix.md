## 원인 및 근거 — Sable 릴리스 소스 직접 확인

실게임 0.3.0 로그에는 `PDD-G-MATH-01 POLICY proxyEnabled=false factor=NaN stepCap=NaN`, 승인 에피소드 0, `normalEvidence=NONE`이었다. `ImpactLiveAudit` 라이브 코드가 정확/근사 법선 입력에 모두 null을 공급했으므로 단순 설정만으로 positive live budget을 검증할 수 없었다. 기존 `G-COL-02` 양측 블록 검증은 정상이며 좌표 일치 조건을 다시 강제하면 안 된다.

Sable 업스트림 GitHub **릴리스 태그 `mc1.21.1-2.0.6-neoforge`** 소스를 직접 확인했다.

1. `sable_rapier/src/main/rust/rapier/src/hooks.rs` (`modify_solver_contacts`)는 법선 상대속도를 계산한 뒤 `velocity = velocity.abs()`로 변경해 Java 콜백에 전달한다. **`impactVelocity`는 접근/이탈을 구별할 수 없어 근사 예산의 근거가 될 수 없다.**
2. 같은 파일 `handle_block_params`는 `block_coord_d = isometry.inverse_transform_point(global_point) + center_of_mass`를 콜백의 `impactPosition`에 제공한다.
3. `common/src/main/java/dev/ryanhcode/sable/api/physics/callback/BlockSubLevelCollisionCallback.java` 공식 API Javadoc은 콜백 `impactPosition`이 hit 블록의 Plot 좌표(정적 세계 블록은 global 좌표)라고 명시한다.
4. Rapier 네이티브 15-double 효과 feed는 기존 명세대로 단순 진단용이다. 사전 solver 단계의 정확한 방향 또는 접점 근거로 임의 승격하지 않았다.

### 절대적인 능력 제한

- `BLOCK_FACE_ESTIMATE`는 **저비용 방향 추정치**이다. Sable의 정확 solver normal이나 정확 접촉점으로 주장하지 않는다.
- **일반 full-cube 정적 블록이 hit인 경우만** 현재 실게임 proxy 승인 후보이다. 다른 Plot끼리·회전 지배·비정형 충돌·모서리는 근거가 없으면 0으로 안전하게 거절한다.
- `P-16` 은 기본 off. 인게임 실험용으로만 `-Dpdd.proxy.enabled=true -Dpdd.proxy.factor=0.5 -Dpdd.proxy.stepCap=100.0`을 명시한다. 이 값은 **밸런스 정책 확정값이 아니다**.
- 0.3.0에서는 **세계 블록, Plot, 충돌 callback을 변경하지 않는다**. 충격 예산은 진단 데이터이다.
- 유효한 프록시라도 출력 크기는 실험 정책에 의해 달라진다. Rapier impulse/물리적 줄 단위가 아니다.

## 인게임 테스트 — 최대 2회 실행으로 검증

### 1회차 — Proxy off, G-COL-02 회귀

1. Actions로 JUnit·Build 성공을 먼저 확인하고, 새 `physical-destroy-deform-0.3.0-fix.jar`만 설치한다(구 0.3.0 JAR 중복 설치 금지). Minecraft 1.21.1 + Sable 2.0.6 + Create 6.0.10 + Aeronautics 1.3.2. **JVM `pdd.proxy.enabled` 기본 off**로 실행.
2. 일반 월드 잔디·돌벽과 물리 Plot 충돌, 서로 다른 Plot끼리 충돌, 회전·다중 접점·정지·끼임, 가능하면 Belt/Fragile 콜백을 한 세션에서 실시한다.
3. 예상: `[PDD-G-COL-02] phase=QUALITY targetOutcomes=...`, 실제 UUID·블록 ID를 포함한 `TargetKey`, `pairMatcher=DIAGNOSTIC_ONLY`, `[PDD-G-MATH-01] POLICY proxyEnabled=false`, `phase=SUMMARY ... approvedEpisodes=0 reasons={POLICY_DISABLED=...}`, `mutation=OFF`.
4. **합격:** 유효 양측 소유자·원본 callback 결과 유지, 0 예산, 안전 거절. **실패:** 미확정 타깃 임의 승인, Sable 원본 반응 변경, PDD 세계 파괴, 예외·크래시. 특수 콜백 없으면 해당 회귀는 **미관측**으로 보고.

### 2회차 — Proxy on, 실제 양수 근사·안전 차단

1. 게임 재시작 시 JVM 인수: `-Dpdd.proxy.enabled=true -Dpdd.proxy.factor=0.5 -Dpdd.proxy.stepCap=100.0` (시험용). 넓고 평탄한 **일반 바닐라 돌 큐브**로 표면 만들고 Plot을 **병진 낙하**시켜 벽/바닥의 중앙 단일면으로 충돌시킨다. 회전은 처음 최소화한다. `world` 블록이 콜백의 `hit`이어야 하며, Sable 콜백 법선 속도 값만으로 승인하면 안 된다.
2. 예상 승인 로그: `[PDD-G-MATH-01] phase=INPUT ... normalEvidence=VERIFIED_WORLD_CUBE_FACE ... normalBtoA=...`, 이후 `[PDD-G-MATH-01] phase=APPROVED ... budgetKind=CONSERVATIVE_PROXY source=BLOCK_FACE_ESTIMATE:VERIFIED_WORLD_FULL_CUBE_SINGLE_FACE ... budget=양수 worldMutation=OFF`. **첫 검증 가능한 접근에 양수 예산이 한 번 이상 승인되는지 확인한다.**
3. 같은 Plot을 정지·끼임 상태로 유지하고 후속 step에서 `DUPLICATE_EPISODE`가 기록되는지 확인한다. 분리 뒤 재충돌하여 새 사건만 승인되는지 확인한다. Plot A–B, 회전이 지배적인 스침, 모서리 충돌에서 미확정이면 `ROTATION_UNRESOLVED`, `DIRECTION_UNVERIFIED`, `SEPARATING_OR_TANGENTIAL` 등으로 **양수 예산을 거절**해야 한다.
4. **합격:** 적어도 한 건의 승인된 유효 정면 접근에 양수 Proxy, 잘못된 방향·스침·연속 접촉 거절, 물리 단계 cap 초과 0, 정확 모델/근사 중복 0, 세계 변경 0, 원본 callback 결과 동일. **실패:** 이론상 유효하고 설정된 정면 접근도 무조건 예산 0, 미검증 위치 또는 방향에서 양수 예산, 한 지속접촉의 반복 누적, 의도치 않은 피해/크래시.
5. Plot-Plot 근사 방향은 아직 독립 검증된 입력 출처가 없으므로 양수 승인 **필수 아님**. 설계서 1.0.3은 모든 충돌 정밀 접점을 0.3.0 합격 조건으로 요구하지 않는다.

## GitHub Apply 인계

1. GitHub `main` 최신 HEAD가 위 SHA와 같은지 확인한다. 다르면 변경 파일을 재대조한다.
2. 기존 `incoming/`에 단 **하나**의 전체 소스 ZIP만 올려 `Apply PDD ZIP`을 실행한다. 이 ZIP 안에는 `.github/`, `.git/`, `incoming/`, `gradle/`, `gradlew`, `gradlew.bat`가 없으며 Apply가 기존 GitHub 파일을 유지한다.
3. `PDD Manual Build`를 실행해 `test`, `build`, `compileJava`, `compileTestJava`, 리소스/JAR 성공과 JUnit 결과를 확인한다. `PDD Callback Contract Test`의 원본 콜백 회귀도 확인한다.
4. 성공 빌드 JAR을 2개 세션으로 인게임 검증한다. 실패 시 테스트를 삭제/우회하지 않고 오류 로그로 원인을 특정한 다음 전체 Gradle 검증을 반복한다.

**미검증 사항:** 실제 Gradle 의존성 해석, 공식 JUnit 총 성공 수, 새 CI, 인게임 정면 충돌의 live 승인, 성능, Sable 외 다른 모드와의 모든 콜백 회귀. 전부 합격하기 전 `빌드 검증 완료` 선언 불가.
