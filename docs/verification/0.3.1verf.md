# PDD 0.3.1verf — verification-only instrumentation

**Scope:** IDS 1.0.5-A, especially §§21.3–21.5, 22.1–22.5, 23 and 26. This is the unchanged PDD 0.3.1 credit policy with **additional evidence traces**. Source basis: GitHub `main` commit `4751e904b032ec025935e54ac5a80ee0b15501d3`; zip source confirmed against the GitHub tree and sampled exact blob hashes. Minecraft 1.21.1; NeoForge 21.1.x; Create 6.0.10; Aeronautics 1.3.2; Sable 2.0.6; Java 21.

## 1. Engineering changes and acceptance intent

1. `GameImpactCredit.EvidenceSnapshot` exposes **read-only** FSM state before/after `step()`: phase, last Java server tick, gap samples, pending authorization, burst frame number, episode and generation, authorization tick. The `step()` decisions, thresholds, Q, share ratios and original Sable callbacks were not intentionally modified. `POLICY_REVISION` remains `PDD-IDS-1.0.5-A/0.3.1`.
2. `SableContactRegions.Trace` preserves the precise reason a **source-correlated** contact region failed, identifying native record index, A/B remaining inspection budget, inspector request, targets collected before failure, region limit and first rejection details. The sampler is not a new target authority; ambiguous contact still maps to `Q=0`.
3. R4 diagnostic `RealFixBoundaryCandidates.Result` reports exact contact point at which candidate cell budget/union exceeded its limit, source point count, cell count and reason. The world-block probe remains provisional and **cannot issue Q**.
4. `RealFixRuntimeBridge` logs conditional new `PDD-VERF-*` observations. The log records both **native world tick** (`nativeTick`) and **MinecraftServer.getTickCount()** (`serverTick`); `authorizationTick`, `separationEvidenceServerTick` and `lastContactServerTick` are in **server tick units**, not native/world tick units.
5. Four new regression methods cover non-mutating FSM snapshots, pending evidence consumption, differentiating over-target and cell budget, uncorroborated contact, and R4 candidate-budget failure (plus all original tests preserved). Existing telemetry and budget logs are retained.
6. Version metadata `0.3.1verf`, `worldMutation=OFF`. No block damage, deformation, world edits, callback replacement, JNI change, or force-Q threshold adjustment.

### New structured log tags

| Log tag | Important fields and interpretation |
|---|---|
| `[PDD-VERF-SEPARATION]` | `source=PRECONTACT_CLEARANCE` or `OBSERVED_AABB_GAP`; state before/after, separated samples, known AABB gap. A missing record is **not proof** of separation. |
| `[PDD-VERF-FSM]` | source/native tick vs server tick, state before/after, pending before/after, `burstBefore/After`, `authorizationBefore/After`, `evidenceAge`, `authConsumed`, previous/now gaps, `aabbClosing`, target quality, episode generation, Q, reason. An `ACTIVE → APPROVED` with pendingBefore=true, authorizationTick from an earlier `ARMED` and `burstBefore < 2` can be legitimate deferred credit. If no valid authorization chain exists, investigate as a defect. |
| `[PDD-VERF-REGION]` | `failure`, `failedRecordIndex` (index of **current source array**, NOT an enduring manifold ID), checks, remaining budgets, targets/regions before rejection, raw native point and consumer-local candidate, owner frame UUID, initial empty-side reasons. `SIDE_*_INCOMPLETE` details distinguish R2 cell budget and R3 reserve; `TARGET_LIMIT_*`, `REGION_LIMIT`, `CHECK_BUDGET_*`, `OWNER_MISMATCH_*` distinguish safety caps. |
| `[PDD-VERF-R4]` | shadow-only result, exact excessive `CONTACT_POINT` index, `UNIQUE_CONTACT_CELLS_EXCEED_BUDGET` versus `POINT_CELL_COUNT_EXCEEDS_BUDGET`, union cell count, R4 remaining tick quota and swept AABB. `credited=false` is mandatory. |
| `[PDD-LEDGER]` | existing authoritative allocation reservation: regions and both per-block A/B reserved Q shares. Compare totals to `[PDD-VERF-FSM] issuedQ`; an event with zero grant is not damage. |

**Sampling/overhead:** New `[PDD-VERF-REGION]`, `[PDD-VERF-R4]` and `[PDD-VERF-FSM]` rejection records appear on first observation, on a change of cause/state, and then no more than once per pair/cause per 100 server ticks while stable. Approval and phase changes are logged immediately. Set `-Dpdd.verf.enabled=false` to disable verification-only logs; `-Dpdd.verf.sampleTicks=100` changes sampling (lower bound 20). Original baseline `[PDD-...]` logs are retained unchanged. The new diagnostics are read-only; per-pair state is already bounded by the production ledger cap.

## 2. Reproduce in at most two in-game sessions

**Test structures (unchanged):** A1: stationary stone wall; A2: stationary grass floor; B1: rope-connected levitite handle and reinforced deepslate+chain flail; B2: balloon gasbag and burner-weight Plot; B3: stone-wall Plot. Record the Minecraft version, installed mod build name, wall placement and the rough start/end time of every test.

**Session 1 — B1→A1, B1→A2:**

1. Start server/world; confirm `[PDD-DIAG] ... version=0.3.1verf`, `[PDD-0.3.1verf] phase=START` and `worldMutation=OFF`.
2. Hold B1 separated from A1 for at least two stable physics observations. Drive B1 into A1 once, then continue pressing/sliding against the same stone wall without withdrawing. Repeat after clearly pulling B1 away from the wall for at least two stable observations.
3. Repeat step 2 on A2 grass. Ensure at least one distinct direct landing and sustained stationary contact.
4. Record visual contact block coordinates when possible, especially when a `TOO_BROAD` record is emitted; collect entire `latest.log` from start to world exit.

**Session 2 — B1→B2, B1→B3:**

1. B1 and B2 separated for at least two observations. Strike gasbag/weight one at a time, then maintain contact; separate and re-strike. If possible try two distinct contact locations on one pair without separating, to check whether they are incorrectly treated as independent episodes.
2. Repeat using B3 stone-wall Plot with B1 reinforced-deepslate head, including one full withdrawal and re-strike; note the two Plot owner UUIDs if available.
3. Keep whole `latest.log` through the stop log; do not copy only APPROVED lines because **prior separation and ARMED evidence** can be much earlier than the approval.

**Success conditions:** source-proven `APPROVED` matches an independently verified, unspent ARMED authorization; sustained contact has no extra Q without new proof; rearm after verified separation yields one new generation; `PDD-LEDGER` A+B+unused equals issued Q (subject to float tolerance), target owner IDs and inspected coordinates match; `TOO_BROAD` logs state **which exact candidate/inspection/target/region budget** was exceeded; R4 remains diagnostic; no exceptions, crashes, block edits or callback regressions.

**Failure evidence to send:** full `latest.log`, GitHub Actions compile/test/build logs for any failure, test pairing and approximate tick/time range, observed impact block(s); if a collision is visually missed, its screenshots/video can help distinguish R2/R3 false negatives from genuinely broad regions. Do not confuse `nativeTick` with `serverTick` when tracing authorization.
