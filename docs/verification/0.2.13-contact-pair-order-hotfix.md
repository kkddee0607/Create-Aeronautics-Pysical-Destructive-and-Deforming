# PDD 0.2.13 — ContactPairMatcher 결과 순서 회귀 수정 (IDS 1.0.2)

## 기준과 오류

- GitHub `main` 기준 SHA: `cb6890450bcac1f4b120821bd846335ebc5d30ac` (2026-10-30 UTC).
- 소스 입력: `PDD-0.2.13-IDS-1.0.2-owner-local-full-source.zip`, GitHub `main`의 같은 테스트·매처 파일을 대조함.
- 사용자가 제출한 GitHub Actions Build PDD JAR 로그: Gradle 8.10.2, Java 21, NeoForge 1.21.1 아티팩트 생성·`compileJava`·`compileTestJava`·`processResources` 성공, JUnit 49개 중 48개 성공/1개 실패.
- 실제 실패 지점: `ContactPairMatcherTest.java:83`의 `assertEquals(2, result.matches().get(0).second())`. 79번째 줄의 매칭 개수 검증이 아니라 **매칭 결과 내 두 콜백 인덱스의 순서**가 실패한 것임.
- 원인: `ContactPairMatcher.match`가 `HashMap<PairKey,...>` 순회 중 먼저 방문한 방향을 `Match.first`로 사용. 역방향 key가 먼저 방문되면 동일한 실제 쌍을 `(2,0)`으로 반환. Plot UUID 해시 및 콜백 간 삽입 순서에 영향을 받으며, 소유자 좌표 변환이나 Sable 콜백의 문제라고 증명되지 않음.

## 수정 범위 및 API 계약

- `src/main/java/com/physicaldestroydeform/collision/ContactPairMatcher.java`: 역방향 쌍을 찾은 뒤 인덱스 `min`·`max`로 정렬해 `first`/`second` 및 `firstEvidence`/`secondEvidence`의 대응을 보장한다. 여러 독립 쌍도 `first` 인덱스 기준 정렬해 반환한다.
- `src/test/java/com/physicaldestroydeform/collision/ContactPairMatcherTest.java`: 기존 기대값을 완전히 보존. (1) 고정 UUID 조합 512회, 회전 독립 Plot A↔B와 끼어든 단독 샘플 상황에서 안정 인덱스·Evidence 일치 검증; (2) 두 독립 쌍의 입력 순서에 따른 결과 정렬 검증 추가.
- **변경하지 않음:** 원본 Sable 콜백과 반환값, `CollisionFrame` 좌표·OwnerResolver 타깃 계약, epoch/차원/역방향 고유 매칭·다중 접촉 모호성 검증, 기존 0.25 진단값, NeoForge·Gradle·JUnit·Java 설정, GitHub Actions 및 Apply ZIP 보호 파일 정책.
- IDS 1.0.2의 `TargetKey`와 Plot별 고유 BlockPos 및 추후 손상/파괴 적용 경계 유지. 0.2.13에서 손상 계산·블록 mutation을 활성화하지 않음.

## Apply ZIP과 검증 인계

- ZIP은 `PDD-0.2.13/` 단일 Gradle 프로젝트 루트와 전체 Apply 동기화 대상 소스·문서·테스트를 포함한다. `.github/`, `incoming/`, `gradlew`, `gradlew.bat`, `gradle/`은 **기존 GitHub Apply 워크플로가 보호·보존**하므로 ZIP에서 의도적으로 제외한다. 기존 파일이나 버전은 변경하지 않는다.
- 업로드는 사용자가 GitHub `incoming/`에 ZIP 하나만 넣어 수행. Apply가 완료된 후 별도 PDD Manual Build에서 `./gradlew test --no-daemon`, `./gradlew build --no-daemon`을 실행. 추가로 가능하면 `./gradlew clean test --no-daemon`도 실행한다. 관련 Callback Contract Test와 Apply ZIP 액션 결과는 별도 확인해야 한다.
- 인게임 시험 최대 2회: (1) 정적 잔디/돌벽과 물리 Plot 및 두 번째 Plot의 연속 충돌, (2) 상대 회전된 Plot↔Plot 동시 다중 접촉. `targetVerifiedBoth`, `verifiedWorldPlot`, `verifiedPlotPlot`, `pairAmbiguous`, 샘플의 각 `TargetKey`가 실제 소유자와 블록 좌표를 가리키는지 검사. **원본 Sable 동작 보존, 비정상 스텝 미승격, 월드 mutation=0** 확인. 자세한 기대 로그는 `0.2.13-ids-1.0.2-owner-target.md` 참조.

**현재 판정:** 사용자 보고 빌드 실패의 재현 가능한 원인인 매처 결과 방향 문제는 소스에서 수정·보조 검증 완료. 공식 Gradle/JUnit, GitHub Actions 및 인게임 검증은 미완료이므로 최종 빌드 검증 완료 아님.
