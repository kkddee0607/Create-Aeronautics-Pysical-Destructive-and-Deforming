## Root cause and correction: first Plot/Plot contact

At B1–B2 first contact, `serverTick=903`, `phaseBefore=ARMED`, `separatedSamplesBefore=896`, `separationEvidenceServerTick=-1`, `prevAabbGap=UNKNOWN`, `reason=APPROACH_UNVERIFIED`, `Q=0`. The owner-local R2 audit had succeeded on both sides. Evidence indicates loss of the bridge's `Tracked` object while `GameImpactCredit` preserved its `ARMED` state.

`RealFixRuntimeBridge` previously pruned `Tracked` after `now-lastSeen>600`; `lastSeen=-1` for pairs that were **continuously verified separated but had never contacted**. `credit.step` kept ARMED via fresh independent separation evidence every tick, whereas the `Tracked` object holding `lastSeparatedTick` and previous AABBs was deleted on the next 100-tick prune. This caused `armedFromGap=false` on the first actual Plot/Plot contact despite 896 positive samples.

**Fix:** prune tracked history from `lastProcessed`, which advances only when the bridge processes a verified separation or an observed contact. Keep `lastSeen` as the separate last-contact timestamp for contact-after-gap invalidation. Keep a bounded 600-tick idle expiry and 4096-pair map cap. No force-only approach shortcut; no changes to the native callbacks, collision solver, R2 proof, two-clearance rearm or Q ledger.

## Developer-game budget change: saturation

Existing QFix game proxy: `Q=min(64, 0.25*max(0,F-2))`. This reaches Q=64 at `F>=258`; the six observed first-approved force proxies were all far above it.

DuperFix preserves the **linear bounded, first-approved-force** model and absolute Q cap, but changes only the version's `DEV_PROVISIONAL forceGain` to `0.001`:

`Q = min(64, 0.001*max(0,F_first_approved-2))`, with `forceEnter=2`, `forceFloor=2`, `maxGroupQ=64`.

Example measured inputs: `F=3849.2827 -> Q=3.8473`; `F=30181.8867 -> Q=30.1799`; `F=52421.02 -> Q=52.4190`. Saturation starts at `F=64002`. These values improve resolution for **this** test range, not an established balance or joule/impulse conversion. The original policy remains testable with explicit legacy `Settings(2,2,.25,64,2,4096,600)` and operators can override runtime gain with `-Dpdd.realfix.forceGain=...` on the Java launch process. No previous credit is recalculated; world mutation remains disabled.

## Regression and invariant checks

1. B1–B2 pre-contact clearances maintained for >600 ticks must retain the same `Tracked` evidence; first valid Native/R2 collision must authorize exactly one Q even if last contact was never recorded.
2. A1 World/Plot `WorldClearanceVerifier` must continue requiring two positive independently completed full clearances. `BLOCKED`/`IN_PROGRESS`/`TOO_BROAD` do not authorize. Plot/Plot uses real AABB separation.
3. Sustained contact, 100 native record cap and repeated force increases must not mint extra Q. Side 32-cell and target caps, R3/R4 diagnostic quarantine, owner generation, and `Q=sharesA+sharesB+unused` are unchanged.
4. `ForceCalibration` still records first *issued* grants only; its `saturated` count must reflect the new threshold and never issue credit itself.
5. Existing regression tests (including F=42 yields legacy Q=10) are retained by selecting the explicit historical profile, not by deleting tests.
