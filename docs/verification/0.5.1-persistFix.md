## Baseline and scope

GitHub main: `011686358f62114a29a8565895e57404bab4f525` (Apply PDD ZIP update).

IDS 1.0.8 §9.3, §24 recovery: payload-less DEFERRED is aborted; PREPARED is uncertain and never replayed. The new schema stores the previously missing payload, so a never-executed intent can resume without new F/Q authorization.

- World and Plot share the same new schema-3 receipt codec and bounded commit core, but retain their independent WAL directories and namespaces.
- The DEFERRED frame stores the original ApplyId/key/incarnation, exact double Q, material fields, material generation, F-first flag, original tick, DamageModel settings, admission order and game-time expiry. No extra per-intent fsync is introduced. Payload is removed from the live receipt when PREPARED or terminal.
- Replay restores only payload-bearing DEFERRED, never PREPARED/APPLIED/ABORTED/PARTIAL_QUARANTINED. Legacy schema-1/2 receipts without payload retain the existing fail-closed behavior.
- Clean stop checkpoints the current rotated queue order. Crash before publication restores the last committed order plus subsequent WAL admissions; exact arbitrary crash scheduling is not guaranteed.
- The original server-tick TTL applies in the live run; recovery uses the saved overworld game-time deadline so a restart does not renew that budget. A hard crash may roll back Minecraft's independently saved world clock/state.
- World replacement tracking includes pending-only cells. Plot restore validates UUID, owner-local key, saved center/fingerprint/incarnation and revision; no runtime body ID or HeatMap witness is persisted. Missing/unloaded owners wait, changed or unprovable owners cannot mutate, split/orphan and ambiguous PREPARED are vetoed. No forced chunk loads, new physics calls or new source Grant.
- DamageModel, material CSVs, F/Q ledger/propagation, cap 64 World / 32 Plot, 1-tick Plot pacing, HeatMap/pending/witness checks, protection, native drops and deformation preview remain unchanged. An old stored intent is planned using its original numerical settings and current validated accumulated state.

## User validation

Back up the entire world before using schema 3. Do not downgrade without a matching backup.

1. Apply the full-source ZIP, run PDD Manual Build and Callback Contract Test, install the resulting JAR with Sable 2.0.6. On a disposable world, collide a Plot with ordinary blocks and exit while Plot or World pending is nonzero. Reopen without a fresh strike. Look for `[PDD-RECOVERY] phase=START ... restoredPending=N ... intentPayloadPersisted=true` and `[PDD-PLOT-RECOVERY] phase=START restoredPending=N`. The same ApplyIds should produce RESULT/COMMIT as valid targets load; pending should drain or show a legitimate veto/expiry. Verify no duplicate drops, no fresh Q for restored intents, no Sable error.
2. Repeat with an interrupted/removed target or split parent. Recovery must not apply ghost damage to a replacement or child. PREPARED remains quarantined. Submit latestlog.txt including initial pending counts, startup recovery and terminal commit results if either test fails.

Earlier fastBreakFix ABORTED receipts cannot reconstruct lost Q. Existing numerical damage is retained, but previously discarded work cannot be recovered. In-game split/collider/native-save correctness is still subject to the inherited safety limitations; do not claim cross-mod exactly-once transactions.
