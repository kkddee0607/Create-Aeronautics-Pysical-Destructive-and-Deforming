The formula is `v_n=max(0,-(v_A+omega_A×r_A-v_B-omega_B×r_B)·n)`, `q_i = invM_i + (r_i×n)^T invI_i (r_i×n)`, `m_eff=1/(q_A+q_B)`, `E_indicator=0.5*m_eff*v_n²`. Static environment has inverse mass 0. No unverified scalar, native effect feed, callback count, or contact-frame hypothesis becomes approved energy.

### Remaining runtime capability boundary

The verified Sable 2.0.6 callback ABI does **not** establish a universal world contact point frame, pre-solver unit normal, or `signedVelocity` meaning. The current 15-double native feed may be filtered/post-solver and has no proved same-pre-solver correlation key with the callbacks. Thus, by design, in-game callbacks currently produce an **explicit refusal** to credit exact/proxy energy unless new independently verified input provenance is supplied. This is not equivalent to a positive live proxy test. Exact math and independently validated proxy are implemented/testable using controlled unit inputs; actual live approval is not demonstrated. Resolving these API semantics remains a limit for future in-game exact collision processing and damage, not a reason to fabricate an approach direction.

## In-game test plan — at most 2 sessions

### Session 1: static world vs moving Plot

1. On Minecraft 1.21.1 NeoForge, load Sable 2.0.6, Create 6.0.10, Create Aeronautics 1.3.2, PDD `physical-destroy-deform-0.3.0.jar`. The jar must first pass GitHub Manual Build.
2. Place a vanilla stone wall and assemble a Plot containing ordinary blocks. With game commands or a separate rig, drive into the wall, stop and separate; repeat with a glancing collision. Do not enable any damage from PDD.
3. Look for `[PDD-DIAG] INIT version=0.3.0`, `[PDD-G-MATH-01] SELFTEST status=PASS`, `[PDD-G-COL-02] phase=SAMPLE scenario=STONE_WALL` with verified TargetKeys, `[PDD-G-MATH-01] phase=SUMMARY episodes>0 ... reasons={...}` and `[PDD-G-MATH-01] phase=INPUT` for the actual snapshotted mass/velocity.
4. Expected: `worldMutation=DISABLED`, no extra block destruction; `noOtherCallbacks` (if any) separate from `targetUnresolved`; unverified frame contact must never produce `EXACT_CONTACT` or `CONSERVATIVE_PROXY` budget. Any unexplained approved budget, missing expected capture, owner mismatch, exception or crash is **FAIL**. Count `MASS_INVALID`, `POLICY_DISABLED`, `DIRECTION_UNVERIFIED` reasons as diagnosed gating, not proof of live energy accuracy.
5. Use the default policy **off** for this first session. Record `POLICY_DISABLED` and other independent rejection reasons. No extra game restart is required.

### Session 2: Plot A vs Plot B, rotation, multiple contacts

1. For this second session, launch with `-Dpdd.proxy.enabled=true -Dpdd.proxy.factor=0.5 -Dpdd.proxy.stepCap=100` (illustrative test-only values). Assemble two independent Plots (distinct stable UUIDs). Collide their edges, including rotation and multiple simultaneous block contacts; optionally perform a fragile/belt original callback test when such blocks are installed.
2. Confirm `[PDD-G-COL-02] scenario=PLOT_PLOT`, two different Plot UUIDs and actual block fingerprints. Verify `worldFromHitHypothesis` may diverge without turning `TargetGate` invalid.
3. Check `pairMatcher=DIAGNOSTIC_ONLY`, `noOtherCallbacks` distinct, `[PDD-G-MATH-01]` rejection reasons. `DIRECTION_UNVERIFIED` is expected when owner and mass are valid but no validated normal exists; `approvedEpisodes=0` unless real separately validated contact inputs are implemented. Native effect presence/absence must not cause an invented budget.
4. Verify original Sable collisions/physical reaction and original callback contract remain unaffected; world mutation from PDD remains 0. The session does **not** prove exact contact geometry (deferred to final integration) or performance at 10+ ship load.

**Success criteria:** accurate per-owner block identity, no false coordinate promotion, logged pre-solver mass availability/explicit rejection, exact and proxy unit-test results, no duplicate approved budget, no unintended world mutation, original callback/return behavior. Both sessions cannot by themselves substitute for required GitHub Gradle/JUnit verification.
