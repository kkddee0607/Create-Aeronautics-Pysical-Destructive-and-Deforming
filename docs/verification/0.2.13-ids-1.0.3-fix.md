## 5. ≤2 in-game sessions: exact setup, expected logs and acceptance

**Prerequisite:** Apply exactly one provided ZIP using the existing incoming/*.zip Action; verify the resulting commit; manually run `PDD Manual Build`, and confirm all JUnit tests pass before installing `build/libs/physical-destroy-deform-0.2.13.jar`. Preserve Minecraft 1.21.1, NeoForge 21.1.x, Create 6.0.10, Aeronautics 1.3.2, Sable 2.0.6, Sable optimizer as used in test. Enable JVM property `-Dpdd.debugCollisions=true` (default). Obtain complete `latest.log` each session. Wait at least 100 server ticks after last collision for periodic reports. **Do not expect blocks to break.**

1. **Session 1 (world versus plot + callback preservation):** In an unmodified test world, assemble a small Plot craft with a stone-faced collider or levitite/envelope, place a static `minecraft:stone` wall (plus nearby grass). Collide at low speed, then rotate and collide again. Optional: include a Create belt in the structure and create a contact involving the belt. Sample F3 position and capture actual wall/plot block positions. Expect `[PDD-G-COL-02] phase=SAMPLE scenario=STONE_WALL ... targetOutcome=BOTH_VERIFIED` with one `TargetKey(space=STATIC_WORLD,...)` and one `TargetKey(space=SABLE_PLOT,stablePlotId=...,...)`; `WORLD_PLOT` and `ROTATED_PLOT` examples expected in intervals where contacts appear. For an original callback, `ORIGINAL_CALLBACK` or `BELT_CALLBACK` / `FRAGILE_CALLBACK` and `originalCallbackInvoked=true`; callback identity and count are covered by JUnit contract tests. `phase=QUALITY targetOutcomes` and failure reason counts must be present. `pairMatcher=DIAGNOSTIC_ONLY geometryGate=NON_BLOCKING_DIAGNOSTIC mutation=DISABLED`. Stop/retry only if expected collision did not occur, and check actual block state/Plot ID rather than counting summary alone.
2. **Session 2 (Plot A versus Plot B + multi-contact):** Create two *distinct* independently assembled physical Plot structures (one with stone blocks, one with levitite/envelope). Collide broad face then rotated edge and produce multiple simultaneous contacts, including stationary contact. Expect `[PDD-G-COL-02] phase=SAMPLE scenario=PLOT_PLOT ... targetOutcome=BOTH_VERIFIED`, with **two different stablePlotId values** and actual correct plot-local native `BlockPos` coordinates. `pairAmbiguous` may rise; it must not change `targetOutcome`, nor promote `geometryQuality` beyond `DIAGNOSTIC_ONLY`. **PASS** only when the *specific actual* world/Plot block IDs, Plot identities, read-only state, callback preservation and owner failure handling are checked in logs **and** new FIX Gradle+JUnit+relevant GitHub Actions succeed. **FAIL** if wrong Plot owner or wrong storage BlockPos is `VERIFIED`, callback return/call count changes, a geometry diagnostic causes a valid target to be dropped, an invalid owner becomes verified, the game crashes due to PDD, or any mutation occurs. **UNVERIFIED** if representative samples never occurred or in-game/current CI proof is absent.
