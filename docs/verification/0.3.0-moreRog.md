### Distinguish evidence levels

1. Verified `BlockTarget`/Plot UUID means **callback target identification**, not exact solver contact.
2. Native **post-solver** 15-double effects identify a runtime **body pair** and raw opposing local normals, not their original pre-solver substep. Sable 2.0.6 Java `RapierPhysicsPipeline.processCollisionEffects` invokes `Rapier3D.clearCollisions(long)`, confirmed by actual nested `sable_rapier` JAR signature; existing `RapierCollisionTelemetryMixin` is unchanged.
3. Individual effect-record ordinals are only **array order within this pair/tick**. The available array has no verified `manifoldId`; **`manifoldId=UNAVAILABLE`** in every record. Raw point values are output as `rawPointA_FRAME_UNVERIFIED` / B; not used for exact energy or normal.
4. For successfully validated pair normals, `moreRogSubsteps` independently replays the **existing** translation/rotation policy across every retained pre-solver frame of that pair/tick and shows first failing frame. Only up to four full frame examples are printed; counts and first rejected frame are separate.
5. For rejected pair normals, no rotation conclusion is inferred from an invalid normal. `firstFailure` prints raw/world normals, opposing and canonical inner products and original thresholds for the first rejected record.
6. Voxel-center angular projection is **diagnostic only**; the **actual** rejection remains based on `|ω|×(distance(center, voxelCenter)+sqrt(3)/2×maxPoseScale)` compared to translational closing speed. Not a rotational contact-energy measurement.

### Memory and performance bounds

- Default `pdd.moreRog.enabled=false`. Enabling captures **at most 4 native effect record samples** per owner-pair/tick; a monotonic record count and first rejecting record remain visible after the sample limit. No unbounded raw contact list added.
- Sample strings are computed lazily **at most once per owner-pair episode**, or a second time if a requested focus block pair appears later. Existing 128 ordinary + 32 extra focus-episode log limits remain. Existing `WhyRejectDiagnostics` full counters remain separate from limited output; omission counters remain visible.
- Original game math decisions remain derived from the unmodified policy and pre-solver frames, not any new diagnostic string/trace.

## 6. At most two in-game verification sessions

### Session A — focus block pairs and pure translation

1. Back up world. Load the **new** `physical-destroy-deform-0.3.0-moreRog.jar` only (remove older PDD JAR). Confirm `[PDD-DIAG] INIT ... version=0.3.0-moreRog` and `[PDD-MORE-ROG] phase=CONFIG enabled=true`.
2. Prepare one separately assembled `SABLE_PLOT` stone platform, a movable balloon mass with a chain and reinforced-deepslate weight, and a verified static full-cube stone wall. At least once strike the chain and the reinforced-deepslate against the moving stone Plot, with small angular velocity and a clear roughly linear approach; then strike the static stone wall. Give a complete non-contact interval between distinct strikes for the existing continuity policy.
3. Expected: nonzero `chainPlotStone`/`reinforcedPlotStone` if target pairs are independently observed; per-focused episode `[PDD-MORE-ROG] phase=EPISODE_EVIDENCE ... path=PLOT_PLOT` with `nativeRecordCount`, `firstFailure` or `firstSuccessfulFrame`, `opposingDot`, `commonDot`, `preSolverSubsteps`, `translationClosing`, `omegaRadiusUpper`, `rotationGateRejects`; World–Plot yields `path=WORLD_PLOT` only if face verified. Missing native effects must say so; no invented solver contact or real manifold ID.
4. **PASS** for evidence extraction if each intentionally verified target pairing is seen and the new data distinguishes accepted, no-effect, direction-conflict and rotation rejection whenever observed. **INCONCLUSIVE**, not automatic FAIL, if a particular rejection class does not occur naturally. **FAIL** if API crashes, target ownership flips without evidence, invalid normal mints budget, world mutation occurs, or `moreRog` is enabled but no dedicated evidence log appears despite nonzero episodes.

### Session B — plane vs corner multi-contact and angular motion

1. Reuse the same physical stone platform and collide first on a large flat face (approximately one dominant normal), then the corner while moving/rotating, then pause/stay touching or slide tangentially; ensure opposite sign/impact approach is tested. Keep same flags and capture entire log including summary and any Sable errors.
2. Compare at least one `CONFLICTING_MANIFOLD_NORMAL`: `firstSuccessfulFrame` versus `firstFailure`, `effectOrdinal`, `worldA`, `worldB`, `opposingDot`, `commonDot`, raw local normals and `manifoldId=UNAVAILABLE`. `SIDES_NOT_OPPOSED` must separately report its opposing dot. Check which **verified** native pair reached `rotationRejectSubsteps`, `firstRejectedSubstep` and angular radius versus closing speed.
3. **PASS** if each decision is traceable to original guard threshold, no rejected normal is used for an approved budget, and stationary/sliding contacts do not mint positive budgets. The exact per-record manifold identity and substep mapping remain **UNVERIFIED** because the native API does not supply them; do not interpret them as proof of erroneous solver contact.
4. Check `nativeDroppedTotal=0`, `nativeMalformedTotal=0`, `callbackDroppedTotal=0`, `captureErrorsTotal=0` and `episodeLogLinesSuppressed`; if any nonzero, mark evidence completeness degraded. Test Sable original Belt/Fragile callbacks when a reproducible scene is available; absent such callbacks, mark **NOT TESTED**, not PASS.

## 7. Regression / completion rules

- World–Plot and Plot–Plot approved game proxy branches, no new `EXACT_CONTACT` success claims, no duplicate shared cap, correct `DUPLICATE_EPISODE` and continuity behavior.
- Original Sable callbacks return exactly as prior code; unchanged callback/mixin files and dedicated test workflow must confirm formally.
- NeoForge client/server separation, valid `MassData` and coordinate frames, invalid inputs, native drops and parse errors all remain fail-closed.
- The physics equation and rotational exact mathematical model tests remain; latest source has **106 JUnit test declarations**, all must pass officially before declaring full build validation.
- Remaining risk: a **post-solver force-filtered pair record without a manifold ID** cannot distinguish legitimate simultaneous normal directions versus mis-transformed/temporally mixed manifolds from the same body pair. Diagnostic comparisons may narrow hypotheses but cannot uniquely reconstruct true solver substep/point. Never relax the existing ±0.98 normal thresholds on the basis of an ordinal alone.
- No 0.3.0 world mutation; exact rotating contact in-game evidence is explicitly deferred by IDS 1.0.3 to final 0.9.1 acceptance; no model regression may be hidden by this deferral.
