## Observed QFix test baseline (not superFix gameplay result)

Prior provided `latestlog(1).txt` documents three independently issued Plot/World Q groups, two separation/rearm transitions and no reported native observer/malformed/ledger errors. The third group recorded `SIDE_B_INCOMPLETE` at `checksB=32`, `verifiedB=14` and Q share for World unused. All three Q groups saturated to 64 even though native force proxies varied significantly. ## Changes implemented

1. `OwnerResolver.NativeAuditBatch`: one authoritative live owner/BlockState/VoxelShape audit per new owner/cell; remove the second read and re-check of the same Plot or World cell. Cache immutable `VoxelShape.toAabbs()` output only inside one native group; perform point/shape distance tests for every distinct witness point. Do not reuse per-point proof across different contacts.
2. `SableContactRegions.audit`: preserve existing owner-frame cache and 32-new-cell/side hard bound; append `auditedUniqueOwnerCells`, `reusedCellReads`, `shapePointTests`, `testedShapeBoxes`, `cellBudgetPerSide` to the verification trace. `testedShapeBoxes` is the **sum of box candidates supplied to point checks**, not a profiler count of early-exited shape intersection iterations.
3. `ForceCalibration`: count only *successfully issued* episode-grant first-approved peaks; record raw Q before cap and eight bounded force buckets. It **does not adjust** the Q formula or approve new contacts.
4. `RealFixRuntimeBridge`: report `[PDD-SUPERFIX-CAL]` and `[PDD-SUPERFIX-CLEARANCE-PROF]` every 100 server ticks when `pdd.verf.enabled=true`. Clearance metrics count inspector invocations and elapsed nanoseconds; they are diagnostic only.
5. Version stamps, NeoForge TOML, build metadata, tests, documentation updated. All existing JUnit source tests retained.

### Unchanged safety contract

- Original Sable `clearCollisions` handling; 15-double observation; native buffer max 100 is a saturation flag, not a known count of lost records.
- Owner UUID/generation, COM epoch and independent native A/B witness verification.
- 32 new native-cell reads per side, maximum 32 verified targets per side, maximum 64 contact regions and Q total of 64 (developer provisional tuning).
- Incomplete or over-target side always quarantined; its Q stays unused; successful opposite side never receives the missing share.
- `GameImpactCredit` pair episode state/2-clearance rearm; `ContactCreditLedger` one source credit per generation; R3/R4 diagnostic only.
- `WorldClearanceVerifier` 256 scans/pair/tick, 1024 total incremental/tick, 8192 whole-plot ceiling and same-tick atomic confirmation, 2 positive clearances. No region-only rearm or unverified fast skip.

### Why QFix's 32-cell limit remains

The provided test reports 32 candidate checks on the World side but does not quantify how many distinct collisions need >32 unique owner cells. The previous proposal explicitly requires first measuring cache hit rate and shape lookup cost. SuperFix removes demonstrably duplicate shape reads and adds the missing metrics. It does **not** blindly raise 32 to 64 or distribute Q to unverified cells. Future measured evidence may justify a bounded tuning revision with corresponding JUnit/performance tests.

## Two-session in-game acceptance

### Session A — Plot ↔ World, repeated collision and wide contact surface

1. Install the produced superFix JAR using the existing GitHub Apply and manual-build workflow. Confirm `[PDD-DIAG] ... version=0.3.1superFix` at server startup. Set `-Dpdd.verf.enabled=true` using normal server JVM options.
2. Use a single Plot UUID, collide against a World structure, completely separate, re-collide, separate and collide again. Include at least one contact face with many (>32) Sable witness records, if reproducible.
3. Expected: `[PDD-VERF-REGION]` trace includes new cache/shape statistics, `[PDD-SUPERFIX-CAL]` provides true approved peaks and saturation rate, `[PDD-SUPERFIX-CLEARANCE-PROF]` shows World inspection work. `PDD-EPISODE` and `PDD-LEDGER` are still 1 credit per positive rearm. On `SIDE_B_INCOMPLETE`, the World share remains zero and unused equals Q/2, **not** transferred to Plot. Not all wide contacts must become fully verified.
4. PASS when separate/rearm/recredit events match QFix; target owners, positions, Q conservation and trace counters are consistent. FAIL if duplicate Q appears during continuous contact, a failed side gets Q, Sable callback behavior changes, or inspector reports `CLEAR` with a collider.

### Session B — Plot ↔ Plot, broad-phase and performance

1. Use two distinct Plot UUIDs. Contact, sustain contact, fully separate in World space, re-contact. Test a large Plot near the 8192-cell expanded AABB bound and, separately, one above it.
2. Expected: identical owner-local R2 verification semantics for both sides; two full positive separation proofs before rearm, no Q from R4. Above the 8192 bound, `TOO_BROAD` is safe failure rather than false `CLEAR`. Diagnostic summary displays actual World clearance inspector reads and elapsed time.
3. PASS when distinct owners never alias and every authorized Q equals the sum of target allocations and unused Q. FAIL if old owner generation is reused, R4 invents a target, or oversized World clearance becomes `ARMED` without proof.

Collect full `latest.log`, `[PDD-VERF-REGION]`, `[PDD-SUPERFIX-CAL]`, `[PDD-SUPERFIX-CLEARANCE-PROF]`, `[PDD-EPISODE]`, `[PDD-LEDGER]`, `[PDD-WORLD-CLEARANCE]`, JVM flags, Sable/Create/Aeronautics versions, TPS/MSPT capture, and full failed Actions job logs when relevant. Compare whether new-cell checks, reused points and shape-box candidate counts differ from QFix under approximately identical scenes. Performance improvement is **not** asserted before that comparison.

1. Upload exactly one produced *full Apply-eligible root ZIP* to GitHub repository `incoming/`. Do not upload a partial patch or extra ZIP.
