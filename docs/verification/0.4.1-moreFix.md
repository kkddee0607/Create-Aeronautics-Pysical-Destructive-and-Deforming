## 1. 실제 인게임 장애 원인

업로드된 `latestlog.txt`(2026-11-08 20:52 KST 시작, 총 6605행)에는 0.4.1-Fix3/`Fix3-FACE25`가 로드됐으며, 관찰된 충돌 842개 승인 판정 중 `APPROVED=27`, `DUPLICATE_EPISODE=810`, `INITIAL_CONTACT_UNKNOWN=5`였다. `DUPLICATE_EPISODE`는 지속 접촉에서 정상일 수 있으나, native tick 28506에 `peakForce≈21,323,370`, `aabbClosing=true`, `forceRise≈20,055,831`인데 `ACTIVE`, `issuedQ=0`, `DUPLICATE_EPISODE`, `creditCount=0`인 사례가 있다. 21.3M은 `MAX_GAME_F=40M` 미만이다. **최대값 초과가 직접적인 거절 원인이라는 주장은 로그로 지지되지 않는다.** 최초 접촉 거절 이후 FSM의 ACTIVE 상태와 사전 승인 없는 감사 생략이 보다 직접적인 원인이다.

Fix3 `ContactFacePatch`는 4개 꼭짓점/단일 축정렬 사각형을 먼저 요구했고 검증 실패 시 `NO_CORROBORATED_FACE`로 면 복원이 없었다. 이는 다중 면과 기울어진 면을 정상적으로 다루지 못한다.

## 2. moreFix에서 실제 변경한 경로

- `ContactFacePatch.java`: Sable source-correlated witness의 **각기 다른 평면을 모두 유지**하고, 원래 접촉점의 법선·평면에 따라 각 접촉 패치를 구성한다. 네 꼭짓점 사각형 전제 삭제. 볼록 껍질/선분에 걸친 owner-local 후보를 독립적인 실제 충돌 형상 검증으로 확정한다. 기울어진 평면과 직교하는 다수의 접촉면에 대응한다. 특정 5×5 면을 하드코딩하지 않는다. Source-record 1건·중복 세포만으로 넓은 면을 가짜로 만들지 않고, 개별 후보에 실제 블록 소유자·형상이 증명되어야 추가한다. 동시 복수면은 같은 원인 F/Q 예산 1개만 사용한다.
- `SableContactRegions.java`: R2 근거가 있는 측은 반대쪽의 독립적 검사 상태와 별도로 보수적 면 복원 후보를 유지한다. 별도 `OwnerResolver.NativeAuditBatch.inspect`에서 실제 owner-local 블록/형상/좌표 검증하며 32,768 unique-cell/측, 16,384 대상/측, 32,768 regions 전체 예산을 계속 적용한다.
- `GameImpactCredit.java`: 최초 연락이 `INITIAL_CONTACT_UNKNOWN`으로 처리된 후에도 동일 pair의 **첫 Q 발행 전** 추가로 독립 검증된 접근이 생기면 한 차례 첫 충격 승인 가능. 이미 크레딧 발행 뒤에는 원래 검증된 분리·재무장 필수. 힘이 높다는 사실만으로 인증하지 않는다. `MAX_GAME_F=40_000_000`을 유지하고 `maxGroupQ=forceGain*(MAX_GAME_F-forceFloor)` 관계를 코드에서 일원화한다. 초과 유효 F는 포화 처리한다.
- `RealFixRuntimeBridge.java`: 이전에 동일한 타깃 블록을 확인한 안정적인 World/Plot bounding evidence와 현재 움직임을 비교해 첫 접근을 재검증; 기존 ACTIVE zero-credit 경로의 R2 재검사를 선택적으로 허용. 서로 다른 World 타깃으로 전환돼 생길 수 있는 가짜 접근을 회복 증거로 쓰지 않는다. `PDD-HIGH-F`는 승인/거절과 raw/applied F, cap, 접근 증거를 한 줄로 기록하며 지속 이벤트를 주기적으로 샘플링한다.
- `ContactCreditLedger.java`, `WorldCommitService.java`, `PhysicalDestroyDeform.java`, `build.gradle`, `neoforge.mods.toml`, `README.md`: 활성 릴리스/알고리즘 표시 `0.4.1-moreFix`로 정리. 개별 손상 모델의 역사적 `0.4.0colFix3` 수식 버전명은 알고리즘 자체를 변경하지 않았으므로 유지. 기존 Sable 원본 콜백, 월드 기록/WAL, 이벤트 순서, 서버/클라이언트 분리, 파괴 보호 및 부가 리소스 변경 없음.

## 3. 정적/API 증거와 제약

실제 업로드 JAR: `sable-neoforge-1.21.1-2.0.6.jar`, `create-1.21.1-6.0.10.jar`, `create-aeronautics-bundled-1.21.1-1.3.2.jar`. `javap`로 Sable `SubLevelContainer.getContainer(ServerLevel)` 및 `ServerSubLevelContainer` 등의 공개 메서드를 확인. 기존 프로젝트의 추적·좌표계 어댑터를 보존하고 새 Sable/MC 클래스·메서드 의존성은 도입하지 않았다. 외부 API 전체 Gradle compile/test/runtime classpath 분석은 **실제 Gradle 실행이 불가능해 미검증**이다. 기존 ModDev/NeoForge/Gradle Wrapper 의존성·버전은 임의로 변경하지 않았다.

**중요 한계:** Sable 2.0.6 post-effect 데이터는 완전한 native contact manifold, 개별 접촉 시점의 두 collider pose/shape을 제공하지 않는다. 따라서 새 면 복원은 **source-witnessed, owner-local shape-proven 게임 타깃 근사**이며, 솔버가 모든 확장 블록을 실제 동시 접촉했다고 확증하지 않는다. 서로 떨어진 coplanar 영역의 convex hull이 연결된 owner 형상을 포함할 가능성, 아주 큰/복잡한/비평면 표면, cap=100 native observation 포화, 예산 초과는 여전히 제한된다. 진짜 상호 두 collider 형상 검증·per-contact pose는 네이티브 계측 확장이나 시점 일관된 추가 API 없이는 엄밀히 해결할 수 없다. `MAX_AREA=16,384`는 처리 보호 한계이지 5×5 전용 규칙이 아니다.

기존 세계 적용 계약: static World만 server-authoritative로 변경, Plot은 read-only damage preview. `BlockEntity`, 부정 채굴속도/무적 재료, 위험한 연결된 다중블록, loaded chunk, 소유권 및 blockstate CAS, claim·BreakEvent 보호, WAL/중복 drop 제한 유지. 본 수정본이 1.0.7 최종 목적의 모든 미구현 기능을 완료한 것으로 선언할 수 없다.

## 5. ZIP/Apply 계약 및 사용자 인계

Apply Action은 `incoming/`에 ZIP이 **정확히 1개** 있어야 하며, 내부 `build.gradle`, `settings.gradle`, `src/main/java`의 유일한 Gradle 루트를 요구한다. 보호 루트 `.git`, `.github`, `incoming`, `gradlew`, `gradlew.bat`, `gradle`는 GitHub 리포지토리에서 보존되고 ZIP 내 파일로 덮어쓰지 않는다. ZIP은 **기존 Fix3 Apply ZIP 전체 207개 파일 + 이 검증 보고서**로 구성했다. 테스트 파일과 변경하지 않은 모든 비보호 소스·자원을 유지. 보호 파일은 GitHub main에서 보존되며 ZIP만으로 이들을 새로 교체하지 않는다. 별도의 파일 삭제 없음.

사용자는 ZIP을 GitHub `incoming/`에 단 하나만 업로드한 뒤 Apply PDD ZIP의 성공과 최신 main SHA 변경을 확인한다. 다음으로 PDD Manual Build에서 Java21/JUnit/Gradle JAR 생성의 성공 여부를 검사한다. 컴파일 실패라면 **첫 오류부터 전체 로그**를 공유한다.

### 인게임 검증: 최대 2번

**시험 1 (면·다중 면):** 백업된 별도 월드, 동일 모드팩으로 서로 직교하는 2개 이상의 접촉면과 평면 5×5 이외의 크기(예: 3×8)를 가진 Plot을 월드의 평면·벽면에 충돌시킨다. 내부 접촉 블록까지 손상되고 각 법선의 source record에 대응하는 `PDD-CONTACT-PATCH contactPatch=...SHAPE_VERIFIED_SURFACES faces=N`가 발생하는지 확인한다. 목표는 **사각형 크기와 관계없이 실제 R2 검증된 모든 후보가 기록되는지**이며, 비접촉/빈 형상이 추가되면 실패다. 예상 실패 로그: `NO_PROVEN_SURFACE`, `PATCH_BUDGET`, `OWNER_GRID_OFFSET_UNVERIFIED`, `NO_VERIFIED_REGION` 등. Plot 자체 월드 변형은 이 버전에서 기대하지 않는다.

**시험 2 (대형 충돌·중복 차단):** 사전 비접촉 접근 후 높은 상대속도로 충돌하고, 이어 같은 위치에서 오래 지속 접촉한 다음 충분히 이격 후 재충돌한다. `[PDD-HIGH-F]`에서 `rawF`, `cappedF`, `verifiedApproach`, `recoveryAttempt`, `approval`, `issuedQ`를 확인한다. 큰 힘만으로 기존 ACTIVE 중복을 풀어서는 안 되며, 검증된 새 접근에 대해서는 `APPROVED`, `issuedQ>0`가 확인되어야 한다. rawF>40M 경우 승인된 충돌에서 `cappedF=40M`, 이유 `SATURATE_NOT_REJECT`를 확인한다. 증명 없이 무조건 `APPROVED`이면 실패. 기존 세계 블록 파괴 안전 보호는 유지돼야 한다.

오류 발생 시 `latest.log` 전체, crash report, PDD JAR 파일명, `[PDD-FACE-POLICY]`, `[PDD-HIGH-F]`, `[PDD-CONTACT-PATCH]`, `[PDD-VERF-FSM]`, `[PDD-EPISODE]`, `[PDD-COMMIT]` 로그와 Actions run URL을 함께 제공할 것.
