# PDD 0.4.0colFix3 — 변경·검증·배포 보고

작성 기준: 2026-11-06, GitHub `main` SHA `3da8d75d8dc9a83c89a312e04de2d5304a15e371`.

## 설계 우선순위 / 범위

이 버전은 사용자와 확정한 **다중 접촉점 + 소유자별 네이티브 법선 + 방향성 F 전파** 계약을 우선 구현한다. 통합설계서 1.0.7의 전체 기능을 이번 버전에 도입하지 않는다. 실제 World/Plot 블록 변경, 폭발, 변형, 외부 물성 CSV 로더는 이번 버전 범위 밖이다. 이들은 뒤의 개발 게이트로 남는다.

## 기능적 변경

1. **접촉 시드:** 현재 승인된 `ContactCreditLedger`에서 충돌 블록을 소유자별 중복 제거하고 각 시드에 입력 F를 균등 분배한다. 승인 로직 및 Sable 콜백 반환값은 변경하지 않는다.
2. **실제 벡터와 부호:** Sable effect 15-double 기록의 `local_n1/local_n2`를 각 측의 outward normal로 취급한다. Plot에서는 캡처된 Sable effect `Pose`의 역전치 법선 변환(`FrameMath.Pose.toWorldNormal`)으로 World 방향을 얻는다. World 고정체는 정렬된 좌표계를 사용한다. 각 측 inward normal은 world normal의 부호를 뒤집은 뒤 **자기 소유자**의 로컬 법선 역변환(`toLocalNormal`)으로 계산한다. 변환 결과는 원본 소유자-local 방향과 왕복 대조한다. 소유자/양측 반대성/다중 기록 합치/모든 pre-solver 회전·scale 안정성 하나라도 실패하면 `UNKNOWN`.
3. **Plot 이동/회전:** *충돌 시점*의 검증된 소유자-local 법선과 안정된 블록 격자 키를 한 승인 사건 내내 유지한다. 각 BFS 단계에서 현재의 World 변환을 다시 적용하면 서로 다른 물리 시점을 섞게 되어 금지한다. 매 이웃 방문에서는 현재 Sable 서버 블록의 소유자·지문을 검증한다. 한 사건 도중 Plot 저장 격자 중심이 바뀌면 이후 이웃은 `UNKNOWN`으로 처리한다. 다음 충돌 사건은 자신의 새 프레임과 새로운 승인 증거를 필요로 한다.
4. **방향 제한:** signed 6-neighbor (`DIRECTIONS`)으로 그래프를 확장한다. 로컬 안쪽 단위 법선을 `n`, 시드→대상 격자 차를 `r`이라 하면 `p=r·n`, `q²=|r|²-p²`; `p>=0`, `q<=0.5+p*tan(30°)`를 만족해야 한다. 또한 매 부모→자식 간선의 `step·n>=0`을 요구한다. 반경 `0.5`, 각 `30°`는 캘리브레이션 전 **제안된 게임플레이 정책**이다. 그래프 외부·공백을 중간 블록 없이 뛰어넘지 않는다.
5. **계층형 비순환 전파:** 모든 시드를 깊이 0에 배치해 한 사건 내 BFS를 확정한다. depth `d` 노드는 오직 `d+1` 자식에게 전달한다. 각 부모는 자신에게 온 F 절반을 Q 후보로 환산하고, 나머지 절반에 기존의 자기 탄성 전파계수를 적용해 **그 부모의 실제 자식 수**로 균등 분배한다. 같은 자식에 도착한 서로 다른 부모의 기여는 합산하며 그 자식의 Q는 딱 한 번 계산한다. 동일 간선 이중 반영, 부모·형제·이전 단계 역전파 금지. 부모의 Q에 대한 자식 탄성 감쇠는 기존 colFix2 정책을 유지.
6. **경계/종단:** 검증된 물리적 말단만 미전파 F를 자신의 Q 후보로 수취한다. 방향/미로드/블록변경/노드·깊이 상한 등의 `UNKNOWN` 경계는 미해결 F로 남긴다. 종전 128노드/측, 네이티브 최대 depth 9, 방향 불명 최대 depth 2, Q floor, F/Q 원장 보존 유지.
7. **출력:** 최종 Q는 앞선 물성 모델로 한 번 전달하며 `worldMutation=OFF`를 유지한다. 원래 Sable 충돌 계산·반발·마찰·콜백은 변경하지 않는다.

## 변경 파일

- `ForcePropagation.java`: 전방 cone, 측면 확산, 역행 간선 방지, 기존 다중 부모 합류 계산 유지.
- `NativeEffectDirection.java`: 실제 world/owner-local 왕복 및 비균일 scale 검증, 모든 pre-frame의 linear pose 계약.
- `OwnerResolver.java`, `RealFixRuntimeBridge.java`: 사건별 Plot 저장 중심 일관성 보호.
- `ColFix3DirectionalPropagationTest.java`, `NativeEffectDirectionTest.java`: 신규/보강 테스트.
- `build.gradle`, `neoforge.mods.toml`, 릴리스 메타데이터, Preview 체크포인트 네임스페이스, `README.md`.

## API·외부 의존성

- 새 Sable/JNI/MC 외부 API 호출 **없음**. 기존 `NativeCollisionTelemetry.Contact` effect frame과 `FrameMath.Pose` 경로 재사용.
- `ServerSubLevel#getPlot`, `LevelPlot#getCenterBlock`, 기존 `SubLevelContainer` 조회를 재사용. JAR API가 사용자 대상 Sable 2.0.6에서 다르게 구현되는지 공식 전체 컴파일에서 검증 필요.
- 빌드 의존성 및 JUnit 설정은 기존 그대로. 기존 GitHub Apply/Build/Callback Actions는 ZIP의 보호 경로이므로 **변경하지 않음**.

## 실제 검증 상태

- Java 21 독립 컴파일: `ForcePropagation`, `NativeEffectDirection`, `FrameMath`, `CollisionFrame`, `GameImpactCredit`, `DamageModel`, `NativeCollisionTelemetry` 및 관련 타입 성공.
- 기존 colFix2 + 신규 colFix3 + native normal 관련 JUnit **소스 컴파일**, 호환 최소 어설션 러너의 **23개 독립 체크 통과**. **공식 JUnit 엔진 결과가 아님.**
- Minecraft/Sable API 전체 공식 Gradle 컴파일, `clean test`, `build`, GitHub Actions, 인게임 **미검증**.
- 전체 소스 ZIP은 루트 Apply 보호 파일을 제외한 **168개 기존 파일과 2개 신규 파일**에 변경 사항을 반영해 제공. 최종 패키징 시 ZIP 목록·CRC·압축 무결성 검사.

## 사용자 인계: 최대 두 차례 인게임 테스트

**테스트 1 — World/Plot + 다중 접촉:** 같은 낙하 높이에서 네더라이트·슬라임·돌/슬라임/돌 각각 낙하. `PDD-NATIVE-NORMAL`에서 양측 `ownerVectors`, `PDD-F-LEDGER`의 conservation, `PDD-F-PROPAGATION`의 depth 및 좌표, `PDD-MATERIAL-TARGET` Q를 확인. 넓은 지면에서 4 접촉 시드가 중복 없이 F를 나눠 갖고 Q가 한 블록마다 한 번만 발행되는지 확인. 접속 전에 이미 바닥에 놓여 있던 물체의 `INITIAL_CONTACT_UNKNOWN / Q=0`은 오류로 단정하지 않는다.

**테스트 2 — 사선 회전 Plot + 미로드 경계:** 사선 방향 충돌 및 회전한 Plot 낙하, 그리고 청크 경계를 테스트. World/Plot 모두 법선이 올바른 소유자 로컬 방향으로 나타나는지, 원뿔 바깥/법선 역방향으로 F가 전파되지 않는지 확인. 법선 불명이나 프레임 변경 시 `UNKNOWN` fallback, 미검증 경계에서 미해결 F 기록을 확인. 실제 블록은 변경되지 않아야 한다.

**필수 제출:** `[PDD-POLICY]`, `[PDD-NATIVE-NORMAL]`, `[PDD-DIRECTION]`, `[PDD-F-LEDGER]`, `[PDD-F-PROPAGATION]`, `[PDD-MATERIAL-TARGET]`, `[PDD-EPISODE]`, `[PDD-PREVIEW-SAVE]`, 서버 요약 및 발생한 첫 예외 전체. 기존 Apply ZIP을 `incoming/`에 **하나만** 넣고 `Apply PDD ZIP` 후 `PDD Callback Contract Test`와 `PDD Manual Build`를 확인한다.
