## Root causes from the November 4 0.4.0 game log

- Six observed `APPROVED` collisions: three Plot–World and three Plot–Plot. Forty-three target material plans, zero missing material/plan rejects. Q budget and per-target fixed increment were calculated. All were **independent pristine-state predictions**, since `MaterialPlanner.plan()` called `new BlockDamageState()` for every share.
- `MaterialPlanner.TargetPlan.direction` was always `Optional.empty()`; bridge logs hard-coded `direction=UNKNOWN` for every target, even though the existing `NativePlotDirection` contains conservative opposing-normal and all-pre-substep verification.
- `SparseStateCodec` existed as a pure binary/CRC representation but was never exercised with runtime-approved target states, and there was no game-world restart checkpoint. Consequently `storedEntries=0` and no live preview progression was testable.
- All three are verification gaps, **not proof of invalid native Q or permission to mutate blocks**.

## Implemented read-only verification

1. `PreviewDamageLedger`: bounded (8192 target entries, 8192 incident IDs), server-thread-only shadow state. Computes follow-up `DamageModel` plans using *prior shadow damage/remainder* keyed by dimension, stable owner, owner generation, owner-local xyz and block fingerprint. It atomically stages a whole credit, rejects duplicate `CreditId` and capacity overflow, and never spends any source ledger reservation or changes a Minecraft block. Plastic/stress shares remain explicitly unused, not silently converted to direct damage.
2. Every 100 server ticks after nonempty shadow state, `SparseStateCodec` encodes/decodes live preview entries. This compares full values, verifies schema/CRC, and intentionally flips one copy's payload bit to check fail-closed corruption handling. Logs `[PDD-PREVIEW-CODEC] status=PASS|FAIL`.
3. `PreviewCheckpoint` writes an isolated diagnostic binary at the world root `pdd-0.4.0Fix-preview-only.bin` using a temp file and atomic replacement **only at normal server stop**; it validates schema and CRC on load. At the following start it restores *shadow-preview only*. This file is NOT Minecraft authoritative SavedData, not a pending commit, and must NOT be consumed as actual damage by future versions. `pdd.preview.checkpoint=false` disables file I/O; enabled by default for this verification build. File/CRC failure logs `REJECTED` and preserves an invalid original without overwrite. Filesystem unsupported atomic moves give `FAILED`, never false saved success.
4. Plot–Plot native owner-local directions: reuse `NativePlotDirection.prepare`, which requires matching Sable native body pair and every pre-solver substep to agree on two opposing normals. Additionally require valid owner-mass epochs, non-saturated native source, stable plot UUIDs, and a consistent owner-local signed unit grid axis (>0.98). Only then produce optional `DirectionEvidence`, tagged `ALL_PRE_SUBSTEPS_NORMAL_COMPATIBLE_EFFECT_SUBSTEP_UNKNOWN` (no individual effect/substep ID; `sourceSubstep=-1` means unknown, never guessed as 0). A source that fails any gate remains UNKNOWN with a precise reason. Plot–World normal frame remains UNKNOWN intentionally until authoritative world frame proof is available. No deformation authorization or exact contact claim is implied.
5. Logs: `[PDD-DIRECTION]` for each **credited** collision, `[PDD-MATERIAL-PLAN]` before/after fixed preview total and entry counts, target-specific projected damage and remainder; periodic `[PDD-PREVIEW-CODEC]`, periodic `[PDD-MATERIAL-PLAN] phase=SUMMARY`; `[PDD-PREVIEW-SAVE]` load/write/rejection at server start/stop. All explicitly `mutation=OFF`.

## Two-session in-game verification protocol

**Prerequisites**: Apply 0.4.0Fix full ZIP through existing GitHub Action, execute `PDD Manual Build` and `PDD Callback Contract Test`, install the newly built JAR; remove 0.4.0 JAR so only one PDD mod is loaded. Use the *same saved world* for both sessions. For an uncontaminated check, back up/remove any older `pdd-0.4.0Fix-preview-only.bin` in that world beforehand. Avoid stopping the game process forcibly; only normal *Save and Quit* produces an atomic preview checkpoint. Record console logs with `[PDD-...]` from both sessions.

**Session A — 3 × Plot B1 into static World A1**:
- Place 3×3×3 reinforced-deepslate Plot B1 facing World stone wall A1; keep all relevant chunks loaded. Start from a clearly separated gap.
- Hit A1 with maximal broad face contact, hold roughly 2 seconds, then fully retract; repeat exactly 3 times with a visible gap and enough ticks for two positive clearance samples. Then observe at least one periodic summary, and save/quit normally.
- Expected: three distinct `[PDD-VERF-FSM] reason=APPROVED` events, three `[PDD-MATERIAL-PLAN]` credit events, no second credit while resting, `previewFixedAfter > previewFixedBefore` whenever damage increment is positive, cumulative `previewEntries > 0`, `PDD-PREVIEW-CODEC status=PASS`, `PDD-PREVIEW-SAVE phase=STOP status=WRITTEN`, `committedDamage=0`, `mutation=OFF`. World-side direction `UNKNOWN` with `WORLD_NATIVE_NORMAL_FRAME_NOT_PROVED` is **expected safe refusal**, not a defect.

**Session B — restart then 3 × B1 into Plot B2**:
- Reopen **the same world**, retaining preview checkpoint. Before collision confirm `[PDD-PREVIEW-SAVE] phase=START status=RESTORED entries=... fixedTotal=...` matches Session A stop values. If `status=FAILED/REJECTED`, serializer or filesystem evidence has failed; report it separately, do not claim restart-safe success.
- Collide B1 against Plot stone wall B2 with a broad face for ~2 s; withdraw fully and repeat 3 times. Watch three unique Q credits. For each credit inspect `[PDD-DIRECTION]` with `status`, `reason`, `auditedPreFrames`, and `witnesses`.
- A verified Plot–Plot owner grid direction yields `OWNER_AXIS_CORROBORATED` for both owner IDs; another `UNKNOWN` reason means the exact evidence was not sufficient. **Do not turn unknown into a face guess.** `deformationAuthorized=false` remains required even if orientation was corroborated. Observe periodic `[PDD-PREVIEW-CODEC] status=PASS` after credits, and saved checkpoint again at normal stop.

**Passing criteria**: exactly 3+3 approved credits; no repeated Q while held; budget reconciliation; nonnegative monotonic shadow fixed total across approved damage events; no same-credit reapplication; in-memory codec/CRC veto pass; normal stop checkpoint write and next start restore; runtime recorded direction only on fully corroborated Plot–Plot evidence; all block/Plot modifications OFF. A direction `UNKNOWN` can be an **expected fail-closed result**, not proof that physical deformation is ready.

**Send on failure**: full `latest.log` from both sessions (not filtered snippets), Actions failed job + full compiler error, Git SHA, JAR version, checkpoint `START/STOP` status, Plot UUIDs, whether this was a normal shutdown, exact order/number of contacts, and timestamps. Do not send passwords or access tokens.
