## 실제 수정 및 기능 경계

1. `collision/NativeEffectDirection.java` 신규. Sable 2.0.6 Java Rapier의 실제 15-double 효과 기록에서 World/Plot 각각의 native manifold local normal을 읽고, 소유자/양측 상대 방향/모든 레코드 간 각도/모든 pre-solver Pose와 effect Pose 회전의 일치를 검증. Signed axis 증거는 `DirectionEvidence`로도 연결, 대각선 벡터를 임의 cardinal axis로 만들지 않음.
2. `collision/RealFixRuntimeBridge.java` 승인 후 기존 Credit 경로에 위 native 증거를 먼저 결합하여 공통 World/Plot 전파에 전달. `[PDD-NATIVE-NORMAL]`과 기존 `[PDD-DIRECTION]`, `[PDD-F-*]`를 통해 실제 방향 취득/거절과 전파 예산 확인. Native effect는 **실제 Rapier 법선**이지만 한 레코드의 정확한 substep/solver impulse로는 승격하지 않음.
3. `collision/ForcePropagation.java`에 방향 검증용 bounded 그래프 엔진 추가. 한 부모의 F 절반을 현 블록에, 나머지를 **검증된 자기 자식들에게만** 전달. 합류한 F는 현재 단계에 합산 후 블록 Q 한 번 계산. 탄성체가 실제로 연결된 선행 부모 Q 및 자기 후속 F를 감쇠; 형제 경로의 전역 평균 탄성 오염 제거. WORLD/Plot 공통 neighbor reader와 원장 계약 재사용. 정확한 물리 종단만 잔여 F 전액 인수.
4. 법선 증명된 충격은 앞쪽 좁은 cone, 최대 깊이 9, 측당 128노드, 변환 Q 유효 floor 미만이면 종료. 미검증 방향은 깊이 0..2로 제한하는 비방향성 Preview. 깊이 제한 마지막 층도 실제 다음 이웃을 검사하여 가짜 물리 종단 방지. 보호상한 또는 미로드/미해결은 미배분 F 기록.
5. `DamageModel`에서 자기 탄성에 의한 local Q 흡수를 **한 번** 수행하도록 수정. 이는 다른 블록에 가하는 선행 Q 감쇠 및 자신의 후속 F 감쇠와 다른 대상이므로 중복 감산이 아님. 성능을 위해 `elasticityTransmissionPercent`로 임시 MaterialProperties 할당 제거.
6. `MaterialProfiles`의 Vanilla 슬라임 T는 `max(T,64)`. H=0,D=80,E=100 유지, 사용자 override 우선. **계수 64는 실험적인 내구도 보정값**, 실제 단위/데이터에서 도출된 것이 아님.
7. `ContactCreditLedger`에 기존 legacy signature 유지, 신규 방향 입력 overload 추가. 모든 원인 Q, 동일 에피소드 dedup, A/B 예산 상한, Preview 체크포인트 및 상태 원장 계약 유지.
8. `build.gradle`, `META-INF/neoforge.mods.toml` 및 진단/저장 버전 문자열 `0.4.0colFix2` 동기화. 원본 Mixin 및 Sable callback 동작 불변, 월드 변경 OFF.
9. 신규 JUnit 소스 `collision/ColFix2PropagationTest`, `collision/NativeEffectDirectionTest`, `material/ColFix2ElasticMaterialTest`; 기존 `ForcePropagationTest`의 colFix 당시 자기 탄성 미적용 기대값은 기능 변경에 맞춰 **검사 내용을 대체/강화**, 테스트 삭제/비활성화 없음.

## 실제 API 근거

- 사용자가 제공한 `sable-neoforge-1.21.1-2.0.6.jar`의 내장 `dev.ryanhcode.sable.sable-sable_rapier-1.21.1-2.0.6.jar`를 추출해 `javap` 확인:
  - `Rapier3D.clearCollisions(long):double[]`, `RapierPhysicsPipeline.processCollisionEffects():void`
  - `RapierPhysicsPipeline` 필드 `level:ServerLevel`, `activeSubLevels:Int2ObjectMap<ServerSubLevel>`
  - `processCollisionEffects()`는 15필드 `[0..14]`를 읽으며 `[3..5]`, `[6..8]` 법선 두 개를 보유. 기존 PDD `@ModifyExpressionValue` 원본 double[] 반환/비변형 계약 유지.
- pinned Rust semantics 참고는 통합설계서 1.0.6과 기존 PDD `NativePlotDirection` 소스를 포함한다. 소스 API의 존재와 원본 물리 측정 단위 증명은 다르다. **별도 native ABI·JAR 패치 없이** 실제 배열을 사용.
- NeoForge, Create, Aeronautics, Sable 라이브러리 JAR의 전 클래스·Gradle 종속성 검사는 본 환경에서 **완료하지 못함**. 사용자가 실제 빌드에서 확인해야 함.

## 사용자 인계 — 두 세션 이내 게임 검증

**세션 1 (정적 바닥 + Plot 경로):** 사용자 이전 실험대로 단일 네더라이트, 단일 슬라임, 돌–슬라임–돌 세로 Plot을 각기 자유낙하해 정적 잔디 위에서 충돌. 세 개는 독립 충돌 사건; 슬라임 재반발은 별도 승인된 episode일 때만 추가 처리. `[PDD-NATIVE-NORMAL]`에서 `CORROBORATED` 또는 정확한 거절 사유를 확인하고 `[PDD-DIRECTION]`과 함께 WORLD inward Y- 및 Plot inward Y+ (추정이 아니라 실제 기록된 법선에 따라 달라질 수 있음)를 확인. WORLD `nodes`가 계속 128로 포화되는지, Q floor/깊이/unknown 이유와 F ledger를 확인. Plot 3단의 위쪽으로 전파와 슬라임 경로 감쇠를 확인. 합계 F·Q 예산은 로깅 정책에 맞춰 정산.

**세션 2 (분기·회전·청크 경계):** Plot의 2×2 구조/사선·회전 충돌, 정적 인접 지형 경계, 미로드 청크 근접 사례를 사용. 검증된 native 방향에서 `ownerVectors`가 WORLD/Plot 양측으로 나오는지, 사선 vector가 억지로 cardinal로 바뀌지 않는지, 미검증 방향일 때 `DIRECTION_DEPTH_LIMIT` 또는 `UNVERIFIED_BOUNDARY`이고 실제 종단으로 거짓 전환하지 않는지 확인. 128 상한·오류·낙하 성능을 기록.

**판정:** 원본 Sable 충돌 후 게임 동작 유지, 이벤트당 Credit 1개, Plot/WORLD 소유자 구분, target 중복 없음, `inputF≈assignedF+dampedF+unresolvedF`, `candidateQ≈finalQ+dampedQ`, native normal 증거의 정확한 status, PREVIEW_ONLY(실제 블록 불변)면 성공 후보. `[PDD-NATIVE-NORMAL]`의 거부 사유나 반복 128노드 포화가 있으면 추가 수정 대상. 실제 인게임 성공을 확인하지 않은 상태에서 0.4.1 전환을 자동 승인하지 않는다.
