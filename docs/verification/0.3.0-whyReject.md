## Changed sources and functional behavior

1. `src/main/java/com/physicaldestroydeform/diagnostics/WhyRejectDiagnostics.java` (new): groups independently verified callback block pairs by actual type and owner space, with target-level Plot UUID and allocated `BlockPos`; the first observed representative of each pair also captures pre-solver mass, world linear/angular velocity, available normal, and geometry-quality label. Tracks every candidate `ImpactMath.Reason`, the final post-cap/post-continuity reason, Sable native body-pair gate and source tick/runtime body IDs. Counts Plot chain ⇄ Plot stone and Plot reinforced-deepslate ⇄ Plot stone **regardless of whether any sample log line is emitted**. Does not claim that a body-pair native effect establishes the exact block manifold.
2. `src/main/java/com/physicaldestroydeform/collision/NativePlotDirection.java`: read-only `Prepared.explain(Evidence)` distinguishes `NO_NATIVE_EFFECT_FOR_BODY_PAIR_TICK`, `CONFLICTING_MANIFOLD_NORMAL`, invalid opposite normals, missing/mismatched pre-solver data and validated opposing normals. Never changes `prepare` / `evaluate` / math or callback order.
3. `src/main/java/com/physicaldestroydeform/PhysicalDestroyDeform.java`: logs all eligible `phase=EPISODE` events after the actual shared-step cap and continuity gate (not at initial candidate approval); includes original target pair, physics epoch/server tick, canonical IDs, candidate reason(s), final budget and quality. Outputs 100-tick cumulative `SUMMARY`, `RAW_UNVERIFIED_HIT_TYPES`, full focus-type breakdown and top-type counters. Uses 128 episode lines/tick and a reserved 32 physical-chain-or-reinforced-to-stone episode lines/tick. Suppression counters show any evidence lost from *logging*, while the counters keep counting. If a single approved event would previously have appeared twice with null/non-null normal, now only one Plot record is printed; separate World–Plot and Plot–Plot approvals remain independently visible.
4. `src/test/java/com/physicaldestroydeform/diagnostics/WhyRejectDiagnosticsTest.java` (new, eight tests) and `src/test/java/com/physicaldestroydeform/collision/NativePlotDirectionTest.java` (one new case): check correct static/Plot distinction, precise block-type and Plot IDs, all candidate reasons versus final reason, no-other/unverified separation, cumulative zero/overflow accounting, owner-pair approval not misrepresented as per-block native contact, and absent/valid/conflicting/stale native evidence.
5. `build.gradle`, `src/main/resources/META-INF/neoforge.mods.toml`, `README.md`, `PDD-0.3.0-whyReject-RELEASE-NOTES.md`: only identification/docs updates, no build toolchain change.

### Log schema and semantics

- `[PDD-WHY-REJECT] phase=CONFIG enabled=true ...`: confirms diagnostic path is active; `-Dpdd.whyReject.enabled=false` disables only this diagnostic and **does not disable PDD physics**.
- `phase=EPISODE dimension=... physicsEpoch=... sourceServerTick=... nativeRuntimeIdsCanonicalOwners=... ownerA=... ownerB=... callbackPairs=... loggedUniqueBlockPairs=... omittedBlockPairSamples=... finalReason=... budgetKind=... closingSpeed=... effectiveMass=... budget=... source=... targetPairEvidence=CALLBACK_PAIR_NOT_EXACT_MANIFOLD pairs=[{A=[space=... plot=... pos=... block=...], B=[...], callbacks=..., candidateReasons={...}, nativeBodyPairGate=...}] worldMutation=OFF`: **one final owner pair / physics epoch decision**, not one native manifold or a promise of damage to both blocks. `FOCUS_EPISODE` is identical but uses the reserved log quota.
- `phase=SUMMARY verifiedCallbackPairs=... ownerEpisodes=... approvedOwnerEpisodes=... chainPlotStone=N reinforcedPlotStone=M noOtherCallbacks=... unverifiedCallbacks=... unverifiedReasons=... pairTypes=... pairTypeOverflow=... unlistedBlockPairSamples=... episodeLogLinesSuppressed=... nativeDroppedTotal=... nativeMalformedTotal=... callbackDroppedTotal=... captureErrorsTotal=...`: cumulative. The named Plot–Plot counts **require two independently verified target keys owned by different Plot UUIDs**. `0` means *no verified callback block pair observed*, not absence of a Sable/Rapier solver contact.
- `phase=FOCUS_PAIR_TYPE pair=SABLE_PLOT/... <-> SABLE_PLOT/... callbackPairs=... ownerEpisodes=... approvedOwnerEpisodesAssociated=...`: callback pairing totals. An **approved owner episode ASSOCIATED with that pair** does not prove this exact block face received a native impulse.
- `phase=RAW_UNVERIFIED_HIT_TYPES`: groups non-paired raw hit-block types separately; does not manufacture the missing second owner/target.
- `phase=NATIVE_PLOT_BRIDGE` existing counts plus `nativeBodyPairGate` in episode traces: native effects are filtered, post-solver and tick-wide; no guarantee of all colliders or a per-substep manifold. The native scalar is never used as damage.

### Bounded resources and evidence completeness

- There is no new per-block world state/cache: per-tick episode diagnostics live only during `ServerTickEvent.Post`, then are removed. The session-level pair category map is capped to 256 types; the individual per-episode target pair details to 16; log volume to 128 normal + 32 focus owner episodes per tick. `phase=SUMMARY` discloses all relevant drop/overflow counters. **All seen and verified** chain/stone and reinforced/stone callback pair occurrences are counted even if the generic pair-category table or episode log reaches the cap.
- JNI, callback return values, native 15-double layout, Sable physics snapshots, damage math, world mutation, protected Actions files and Gradle dependency graph are unchanged.
- Bounded logging is intentionally opt-out for this focused diagnostic patch. Disable `-Dpdd.whyReject.enabled=false` for normal performance testing when the 0.3.0 root-cause report is complete.

## At most two in-game sessions, sufficient for IDS 1.0.3 G-MATH-01 diagnosis

**JVM:** `-Dpdd.proxy.enabled=true -Dpdd.proxy.factor=0.5 -Dpdd.proxy.stepCap=100 -Dpdd.debugCollisions=true -Dpdd.whyReject.enabled=true`. Check `[PDD-DIAG] INIT version=0.3.0-whyReject`, `[PDD-G-MATH-01] POLICY proxyEnabled=true`, `[PDD-WHY-REJECT] phase=CONFIG enabled=true`. The 0.5 / 100 numbers are solely test *gameplay policy*, not calibrated physical parameters.

### Session 1 — isolated block-pair proof + World–Plot regression

- Use a separate Sable Plot of full `minecraft:stone` blocks (not static world). Identify its Plot UUID in the log. Move the original balloon so its **bottom chain** has the most direct contact with that stone Plot; separate until at least one full server tick of no contact; then rotate or lower it so the **reinforced-deepslate weight** is the intended contacting surface and collide again. If the bottom chain has a non-colliding VoxelShape, no pair callback is required: retain that as a finding, do not invent one. Keep acceleration and angular speed modest for at least one near-head-on test.
- Repeat the same motion against **static** stone and grass blocks to preserve the old world-cube face estimate. Record (a) the Plot UUIDs; (b) `phase=FOCUS_PAIR_TYPE` and `chainPlotStone`, `reinforcedPlotStone` counters; (c) `phase=EPISODE` lines for verified pairs; (d) the native gate reason and the final `APPROVED`/`DIRECTION_UNVERIFIED`/`ROTATION_UNRESOLVED`; (e) final `nativeDroppedTotal`, `callbackDroppedTotal`, `pairTypeOverflow`, `episodeLogLinesSuppressed`, `unlistedBlockPairSamples`.
- **PASS to classify root cause** if a target pair is observed, both Plot IDs differ, exact block IDs/positions are verified, and a final reason and native body-pair gate are attached. If targeted counts stay `0` with no drop/overflow, only conclude *PDD saw no verified callback pair*, not that no physical collision occurred. If a verified pair exists but final `DIRECTION_UNVERIFIED`, identify specifically `NO_NATIVE_EFFECT_FOR_BODY_PAIR_TICK`, `CONFLICTING_MANIFOLD_NORMAL` or other `nativeBodyPairGate`. A Plot–Plot approval must show only `CONSERVATIVE_PROXY`, never exact contact or world mutation; genuine static stone/grass proxy should still work where valid.

### Session 2 — direction, rotation, tangency, continuous contact and callback regression

- With the same two separate stone/balloon Plots: (1) straight-on approach in both directions, (2) outward separation or sideways tangential contact, (3) rotated/edge/multi-contact collision, (4) resting contact held over multiple server ticks, (5) if available, an original Sable Belt/Fragile callback scenario. Take one uninterrupted log including original callback instrumentation and 100-tick summaries.
- **PASS (in-game proxy/negative path)** when an unambiguous signed approach yields positive `CONSERVATIVE_PROXY` (with explicit correct body-pair normal source), while invalid directions/rotation are refused with a specific reason; repeated resting callbacks must not mint duplicate budgets. No positive budget from abs(callback signed velocity), no pair-to-block attribution without evidence, no world mutation, no original callback return change. A lack of approvals despite trustworthy source should be investigated, not passed by default. `original=0` means Belt/Fragile was not exercised and cannot pass that regression.

### Interpretation and completion gate

A claim that *no chain–physical stone collision was observed* requires `chainPlotStone=0`, confirmation that `PDD-WHY-REJECT enabled=true`, **zero raw callback capture drops/errors**, and acknowledgment that filtered Sable native effects/absent callback still cannot prove no physical solver contact. A claim that a specific block pair *was blocked at the math gate* requires nonzero verified pair evidence plus the corresponding `phase=EPISODE finalReason` and `nativeBodyPairGate` entries. Positive `APPROVED` applies to the **owner-pair budget**, not automatically to all its observed target blocks.

For official **0.3.0** closure, retain from CI: successful `compileJava`, `compileTestJava`, JUnit count/results, `clean test`, `build`, callback tests, artifact/JAR metadata; and from the two in-game sessions: World–Plot/Plot–Plot positive and explicit refusal cases, no duplicate budget while resting, correct target ownership, callback preservation and `worldMutation=OFF`. Real exact rotating contact **integration** remains an explicitly designated **0.9.1** gate under IDS 1.0.3: this patch must not assert that 0.3.0 has proven it. No additional speculative pre-0.3.1 diagnostic version is needed if these supported results pass.
