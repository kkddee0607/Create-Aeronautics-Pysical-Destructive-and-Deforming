## Design and implementation

Sable 2.0.6 bytecode establishes the following path: `sable.mixin.plot.ServerLevelMixin` injects at HEAD of `ServerLevel.tick(BooleanSupplier)` and calls `ServerSubLevelContainer.tick()` when the level is running normally. `ServerSubLevelContainer.tick()` calls `SubLevelContainer.tick()` (ticks sublevels and processes removals), then its holding-chunk map's `processChanges()`. `ServerSubLevel.tick()V` invokes `SubLevelHeatMapManager.tick()V` at bytecode offset 81, conditional on Sable splitting being enabled. The latter runs bounded `step()` iterations and may return without having finished all split work. Therefore elapsed server ticks or `splitComplete` alone are insufficient.

1. Add a read-only observation at the **successful return of the actual HeatMap call in `ServerSubLevel.tick()V`** using exact descriptor, `INVOKE AFTER`, `require=1`, `remap=false`. Store only the current server tick number on that live Sable owner instance. A skipped or throwing call does not grant a witness; no worker/thread or queue is created. If actual integration ordering differs, an absent current-tick witness fails closed.
2. Preserve all safeFix current-value HeatMap checks (`initialized`, `splitComplete`, empty `floodfill`, `removed`, `newStarts`, `subLevelSplits`), live owner verification, split quarantine and CAS after protection events. A current-tick witness is an additional necessary condition, NOT a substitute for the queues being empty or proof of the native solver's health.
3. Default spacing is 1 server tick per `(dimension, owner UUID, generation)`; configuration remains clamped to 1..40. Reserve the attempt before the original irreversible accessor `destroyBlock` call. Only an API=true and verified AIR or matching mutation witness readback marks an attempt confirmed. Unknown/false/exception attempts retain at least the old 3-tick gap, and uncertain receipts are never replayed. Same-tick repeated attempts remain prohibited even if HeatMap is clear. A defensive check is also made at the call boundary, after PREPARED; if this fails, native mutation is not invoked and the existing conservative uncertain receipt handling applies.
4. Preserve queue round-robin and TTL, per-tick 32 total Plot operations, World commit, damage/material settings, drop handling, WAL schema and directory, original collision callback contract, native physics and packets. No artificial deletion effect, unordered/multi-block mutation, forced HeatMap tick, native split rewrite or speculative state migration. No dependency addition. O(1) witness and guard, no new structure scans; bounded existing attempt history pruned as before.
5. `[PDD-PLOT-SAFE] phase=POLICY` reports `tickWitness=REQUIRED_CURRENT_SERVER_TICK`, `breakSpacingTicks=1`, `uncertainSpacingMin=3`. Bounded `WAIT_SABLE_TICK` plus summary `tickWitnessHolds` distinguishes missing tick evidence from pending HeatMap. COMMIT logs carry `serverTick` for validating spacing.

At 20 TPS, the ideal upper bound is one block per Plot every 50ms (20/s rather than 6.67/s); a large hit can still visibly take several seconds, particularly with slow TPS, pending split work, many damage-only intents or a full queue. Naturalness comes from actually committing earlier, not lying to the client or altering the force calculation. Split completion/witness verification takes precedence over speed. `-Dpdd.plotBreakSpacingTicks=3` restores conservative pacing, but never bypasses the new witness.

## User verification in two sessions

1. Start from a disposable matching world backup. Run Apply, Manual Build and Callback Contract Test. Install only the resulting fastBreakFix JAR with Sable 2.0.6. Collide a single connected Plot with a simple wall, using ordinary non-BE blocks. Check policy startup, `serverTick` on `APPLIED_BREAK`, at most one confirmed/attempted break per owner/tick, consecutive ticks when the HeatMap is ready, and `pending=0` eventually. `WAIT_SABLE_TICK` while the owner is active continuously is a runtime integration failure, not permission to bypass the hook. Compare time-to-break with prior safeFix, accounting for TPS.
2. On a copy of a world, conduct a strong collision that cuts a large Plot into fragments and one that destroys a single-cell Plot. Include two independent Plot owners and a protected/BE block. Save, exit, and reopen. Check owner quarantine, no ghost damage transfer, no duplicate drops, correct actual AIR, no `Sub-level assembly attempted inside plot of already removed sub-level` or `Body has been removed`, and both PDD and Sable save success. Supply the complete latestlog/crash report and SableBridge logs if an exception occurs. Optional JVM debug flags: `-Dpdd.tracePhysicsLifecycle=true -Dpdd.traceSublevelPackets=true`.
