## 2. 인게임 증상 및 원인 분석

테스트 로그 `latestlog.txt`는 `0.4.1-moreFix`가 로드되었음을 명시. 이전 분석에서 충돌 에피소드 2,564건 중 승인 45건, 접촉면 패치 시도 61건 중 실제 블록 추가 28건, 추가 0개 33건이 나타남(0개가 모두 오류인 것은 아님). 코드에서 확인한 더 직접적인 기하학적 결함:

- 기존 방향성 `ForcePropagation`은 `ConeField.withinField`에서 `depth<=0`이면 *rootCells* 이외의 모든 동면 블록을 거절했음. 초기 Sable native witness가 꼭짓점 몇 개로 제한되면, 그 주변에 실제 블록이 존재해도 **동일 접촉 평면으로 F가 옆으로 전달되지 않았음**.
- 기존 weight 함수는 0.1 단위 정수 분위와 0.01 tangent fallback으로 배분했음. 사용자가 확정한 전달율(부모 F의 50%를 전달, 전달분의 정면 70%/측면 합계 30%)이 아니었음.
- 기존 `ContactFacePatch`는 2개 이상의 source record와 2개 이상의 서로 다른 평면상 witness를 요구했고, 단일 source witness만 있으면 주변 owner shape조차 검사하지 않았음.

## 3. spreadFix 동작과 의도적 설계 개정

### F 방향성 전파

- 기존 `ForcePropagation`의 owner-local 6면 인접, source-credit 1개, 첫 블록 `localF=incomingF/2`, `outgoingF=incomingF/2`, 탄성 감쇠, 승인·소유자·지문·예산·미확인 경계 보류 및 BFS 다중 부모 합산/중복 회계는 유지.
- native signed normal이 verified일 때, 유효한 자식들을 `Δ·normal>0`인 **내부 방향**과 `Δ·normal≈0`인 **측면 방향**으로 분할. 두 그룹 모두 있으면 outgoing F의 **70%/30%**. 내부 방향 복수 자식은 양의 projection에 비례, 측면 복수 자식은 균등 분배. 한 그룹이 없으면 나머지에 100% 분배. 뒤쪽(`Δ·normal<0`)은 계속 금지.
- 방향이 UNKNOWN이면 검증된 인접 블록에 기존 안전한 동등 분배(방향성 미측정 명시).
- sparse contact에서 좌우 전파를 완전히 막던 `ConeField.rootCells` veto와 고정 geometry cone 제한은 폐지. F 반감, 탄성, `MIN_PROPAGATED_F=1`, `MAX_NODES_PER_SIDE=32768`, actual owner neighbor shape proof 및 중복 방문 금지로 실제 탐색이 한정됨. 원뿔 모양을 인위적으로 보장하지 않으며, 방향 가중치와 경로별 소모로 **중심 우선 자연 전파**를 의도함.
- 예: incoming F=100 → parent local F=50 / outgoing F=50, 자식 정면1+측면2이면 정면35/좌7.5/우7.5. 새로운 native F 또는 Q 크레딧 생성이 아님.

### sparse native contact 근처 보정

- `ContactFacePatch`는 기존 멀티 평면, 임의 형상 볼록 껍질·owner-local shape check를 그대로 유지.
- 소스 관측점이 **한 개뿐이거나 같은 점으로 중복되어** polygon/hull이 불가능할 때도, **해당 소스 평면 위에 기존 R2 verified owner target이 실제 존재**할 경우에 한하여 witness 주변 **1블록 이내 이웃(거리 허용 1.01 cell)**을 owner-local voxel shape로 검증해 초기 접촉 후보에 추가함.
- 실제 차원·owner·좌표 일치 검사, 형상 검사, 16,384 측당 타깃 제한, 32,768 unique-cell 조회 예산 및 단일 F/Q 예산 보존. 로그 `sparseLocalHalos=N`으로 표시. 중복 접촉 또는 근거 없는 owner plane에서 임의로 얼굴 전체를 생성하지 않음.
- **엄밀한 제한:** Sable 2.0.6의 15-double post-effect record는 두 collider의 동시 shape/pose manifold를 보장하지 않음. sparse halo는 *source-anchored game damage approximation*이지, 모든 추가 블록이 물리 엔진에서 실제 접촉했음을 입증하지 못함. 면 전체 정확 복원에는 upstream 고정 시점의 pair collider 증거가 별도로 필요함.

### 기존 통합 설계와의 관계

`docs/PDD-1.0.7-Integrated-Design-Specification.md`의 F-전파 좁은 cone 정책(일부 절에 `perpendicular²≤0.36×forward²`)을 사용자 2026-11-09 최신 결정인 **정면/측면 70:30 가중 분배**가 이번 수정본의 운영 정책으로 **명시적으로 대체**함. 통합 설계 원문은 역사적 문서로 보존. 기존 물리 콜백 반환, 월드 변경 권한, Q-stress, Sable native solver 로직은 건드리지 않음.

1. **시험 A — 접촉면 + 측면 확산:** 기존 월드 백업 후 flat 3×8, 다수 면 접촉 및 꼭짓점만 관측되던 회전·모서리 충돌을 재현. `[PDD-CONTACT-PATCH]`에서 `faces`, `sparseLocalHalos`, `facePatchAddedA/B` 확인. `-Dpdd.f.trace.enabled=true`(디버그용 짧은 실행) 후 `[PDD-F-EDGE]`의 부모·자식 좌표, `directionWeight`, `sentF` 확인. native normal을 따라 정면/측면 모두 자식 존재 시 같은 부모의 outgoing F를 70:30 비율로 보내는지, 원본 접촉점 주변 정면 아닌 블록도 F를 받는지 점검. 인접하지 않는 소유자 블록이나 허공에 피해가 발생하면 실패.

## 7. 미해결 사항 및 안전 경계

- 실제 Sable/Rapier에 native 접촉 패치의 전면 솔버 접촉점/개별 F가 없으면, 동일 시점의 모든 접촉 face가 정확히 증명된다고 단언할 수 없음. 기존 convex hull도 넓은 서로 떨어진 동일 평면 접촉을 병합할 수 있음.
- `70:30`은 물성 실측이 아닌 게임 플레이 가중치이며, 반드시 수학적 원뿔 형상이 나오는 것은 아님. 촘촘한 덩어리/곡면/혼합 normal에서 인게임 검증 필요.
- spreadFix는 1.0.7 전체 통합 설계 기능을 모두 구현했다는 주장이 아님. Plot 영구 구조물 변형/파괴 등 기존 preview 제한은 유지.
- 실 Gradle/JUnit/Actions/게임 성공을 허위로 표시하지 않음. 사용자 ZIP Apply 및 실제 환경 검증 대기.
