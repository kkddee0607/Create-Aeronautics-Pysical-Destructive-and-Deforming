## Algorithm and failure handling

- `data/pdd-stress-0.6.0/*.psr` remains the original v4 active format. `closed-v1/<SHA-prefix>/<SHA>.psc` uses a separate CRC32C-framed schema, storing Credit identity, canonical full reservation/retry hashes, original ApplyIds, exact closed Q ledger/reasons and the digest of the old entry. No frozen node graph or output plan list is retained in the compact record. The in-memory compact index is not constant-size; independent World/Plot receipt ledger and disk capacity still apply.
- Active OPEN records are never compacted. A final SEALED record may be compacted directly after every origin and output has been durably handed off; no second full CLOSED snapshot write. Legacy CLOSED origins are repaired via the same original identity/deadline; each derived output is checked against the actual commit receipt, never blindly reissued. Missing/conflicting output proof retains the old record (`ARCHIVE_WAIT`). PREPARED remains non-reissuable and subject to commit-journal quarantine, not evidence of successful damage.
- Archive writes: create shard, force its parent, write temp+force, atomic rename+force shard, then delete old `.psr`+force parent. If both files survive interruption, reopen compares the exact old entry digest and forces the archive directories before deleting the redundant old copy. CRC/hash mismatch stops recovery instead of guessing. Java 21 NIO API reference: https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/file/Files.html#move(java.nio.file.Path,java.nio.file.Path,java.nio.file.CopyOption...) ; https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/FileChannel.html#force(boolean). Filesystem must support atomic moves and directory sync; no non-atomic fallback.
- Active admission caps remain 8192 records, 4 MiB per record and 64 MiB aggregate, with 2 KiB closing-transition headroom per active record. Only closures of legacy v4 records lacking this headroom can extend the aggregate up to 64 MiB + 2 KiB × active record count, with at most 2 KiB incremental growth per such write; new admission/ordinary planning never use the extension. An admission rejection is explicit and owner-local (`ADMISSION_REJECT`, `QUnused`, `QReissue=false`), not a fresh direct-only hit. Progress pressure retains the durable prefix/cursors, retries when active bytes change or after at most 20 ticks, and keeps the original TTL. Final closure can omit a graph no longer used for planning if required to fit. Unexpected I/O failure remains fail-closed. A legacy record at its exact per-record maximum with no removable graph can still need operator repair if metadata cannot fit; no receipt is silently deleted. At most four archive retirements per tick with a 2 ms soft budget after the first; actual single fsync duration is not guaranteed.
- Active and archived counts are distinct. Startup reads compact identity/ledger indexes but never schedules archived jobs; removes runtime origin watches after completion. Indexed output handoff reduces plan-membership checks from O(n²) to O(n). No change to 4-depth/128-node/512-work/default minQ=1/256/TTL=1200 or H/T/D/E, F/Q, fixed-point, deformation/blocked budget policies.
- Sable 2.0.6 HeatMap caches **pending denial only**, per native manager+server tick; native tick/add/remove invalidate on entry and exit; final destructive mutation and readback still live. Collision log sampling preserves every approval/audit/changed reason/status, first and periodic rejected samples; fullTrace restores pre-existing detail, subject to existing log limit.
- Copycats+ 3.0.11: `copycats:copycat_catwalk` selector refers to an item (CCItems, CopycatCatwalkItem uses CCBlocks.COPYCAT_BOARD); upstream physics-block JSON warning, not a PDD Q fault. Sable `ClientboundSableSnapshotDualPacket.handleClient` skips a missing client sublevel; UDP warning alone does not prove a PDD mutation defect. No external JAR modifications or speculative network workaround.
