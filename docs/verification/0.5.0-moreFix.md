## Observations — separate fact from inference

- Real observed F=54,250,740 and F=310,625,472 from Sable were **already** saturated at `40,000,000` and granted at the old k=0.161; the F ceiling alone was **not** a rejection gate.
- A separate raw F=91,870,360 received `DUPLICATE_EPISODE`/Q=0 and nativeApproach=false, so the rejection was an **episode-authentication** decision. Whether that particular impact was a physically new hit is not provable from that log alone.
- Existing ACTIVE-pair R2 audit required conditions including `quietForceFrames` or special first-hit recovery, so sustained high-force contacts could prevent auditing a freshly hit region. This is a concrete source-level loss mechanism; it does not establish all observed large-Plot failures had this single cause.
- `ContactFacePatch` previously screened *enclosing rectangle area* before actual shape checks; a thin valid diagonal face wider than 16,384 bbox cells was incorrectly omitted. The new scanline checks only candidate bands and individually validates actual owner collision shapes.
- `WorldCommitCore` actually calls `breakVanillaOnce()` then verifies `WORLD_REREAD_AIR`; that receipt is positive evidence for PDD-initiated break success, not simply a pre-existing-air skip.
- Finite F is **Sable post-effect GAME_PROXY**. A measured SI force/impulse or universal force-to-mass-speed proportionality is not established. Do not hard-reject based on an arbitrary factor like 100× mass; this would invent a physical calibration and introduce false negatives.

## 0.5.0-moreFix implementation

1. Current revised default `forceGain` k is **0.1**; cap F at 40,000,000, derived max Q **3,999,999.8** from `0.1 × (40,000,000 − 2)`. Initial moreFix used k=0.25 and Q=9,999,999.5; developer `forceGain` override automatically updates default maxQ; explicit `maxGroupQ` stays as an operator-defined cap.
2. For an already credited ACTIVE pair, after at least two server ticks, check **real native pre-solver approaching** movement *before* performing the costly owner-local R2 audit; at most one such re-audit per two server ticks. Only authorize if new **shape-verified owner-local block** exists relative to last successful credit. Force magnitude alone or fingerprint change in same block does not count.
3. Require at least one pre-solver inward-motion sample, tolerate later neutral substeps, forbid contradicting recession/invalid pose.
4. Use bounded convex-hull scanline candidate queries. Verify source owner and exact local shape on every newly proposed block; reject an incomplete over-budget patch rather than silently count it as a complete surface. Existing 16,384 targets/side, 32,768 shape checks/side and single-event F/Q budget remain; no artificial unbounded memory/CPU increases.
5. If GameImpactCredit approves but ledger does not credit and has no existing receipt, roll back only the unissued credit. Preserve generation monotonicity; require a fresh physical approach before retry; emit `[PDD-Q-ISSUE]`.
6. Preserve existing World actor/claim/CAS, event veto, pre-commit journal, callback order, static-world-only mutation, no forced chunk-load.

## Two-session in-game acceptance / practical validation

**Before both:** Back up an isolated creative test world and `data/pdd-world-0.5.0/`. Keep relevant static World chunks loaded. Enable normal PDD diagnostics. Record Plot shape, size, block material, impact direction, approximate speed, and target static World block identities. Do not compare Plot physical block breakage: Plot mutation remains intentionally preview-only.

### Session 1 — natural impacts and high F cap

- Run a small Plot into an eligible grass/stone World wall. Verify actual World destruction when accumulated damage exceeds material T, and `[PDD-IMPACT-DECISION] gate=APPROVED`, `[PDD-Q-SEAL]`, `[PDD-MATERIAL-TARGET]`, `[PDD-COMMIT]` logs.
- Run the user's oversized grass Plot into a similarly loaded static wall. If the recorded raw F exceeds 40M, verify `[PDD-F-CAP] action=SATURATE_NOT_REJECT`, the **revised** `issuedQ=3999999.8`, `FStatus=PASS`, `QStatus=PASS`, and eligible World block changes. If no World break despite threshold, capture `[PDD-MATERIAL-TARGET]`, `[PDD-COMMIT]` outcome and World block fingerprint / loaded state.
- Comparing same block count alone is insufficient: per-event Q is shared across larger verified contact surfaces; raw F cap limits energy scale regardless of Plot size.

### Session 2 — deliberate detach / reattach and regional contacts

- Keep Plot and wall within loaded chunks. Press the Plot into wall once, **fully separate** it then return at a visibly positive speed to contact a *new face segment*. Repeat at least twice; also hold static pressure 3–5 s as control.
- Success: genuinely new segment generates `[PDD-IMPACT-DECISION] gate=APPROVED regionalReimpact=true` (or a newly ARMED episode), one new Q per independent impact; stationary holding yields `DUPLICATE_EPISODE` and no unlimited damage; changes are bounded to verified World material cells.
- If a new real collision fails: capture `[PDD-HIGH-F]`, `[PDD-NATIVE-TARGET]`, `[PDD-R2-PERF]`, `[PDD-CONTACT-PATCH]`, `[PDD-IMPACT-DECISION]`, `[PDD-Q-ISSUE]`, `[PDD-F-INVARIANT]`, `[PDD-LEDGER]`, `[PDD-MATERIAL-PLAN]`, `[PDD-COMMIT]`, `[PDD-SAVE]` and whether the Plot was truly separated vs slid on a face. Compare native contact source cap status, zero Q, inspected cells, checksum and world mutation errors.

## Unresolved / explicit boundaries

- A Sable-side cap on native records, limited verified shape witnesses, unloaded chunks, a one-side 16,384 target maximum, and the source-once F/Q budget can still restrict large-area deformation. These constraints are deliberately not bypassed by fabricated contact cells or duplicating Q.
- An exceptionally massive Plot does not inherently guarantee every World block is destroyed: bounded total Q is distributed across shape-proved targets, plus elasticity, hardness, and T thresholds.
- A physically meaningful small-Plot / impossible-force veto needs verified **mass, normal relative speed, collision duration and force conversion semantics in the same native epoch**; cannot be responsibly implemented from uncalibrated post-effect GAME_PROXY alone. Existing NaN/Infinity/negative/invalid owner/shape safeguards remain.
- **No world force-loading** or silent eager chunk generation; chunk-load behavior is a separate user-confirmed issue.
