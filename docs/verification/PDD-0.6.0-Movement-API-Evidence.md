# PDD 0.6.0 movement evidence

Scope: local source review and `javap -p -c` on the supplied Sable 2.0.6, Create 6.0.10, and Aeronautics 1.3.2 jars. No Gradle, JUnit, or game execution. The normative requirements are supplied IDS 1.0.8 §§7.7, 24.6, 30.7, and 31, especially lines 765–792, 1896–1900 and 2171–2175.

## Signed owner-local direction

- The 15-double Sable JNI feed contains two `local_n` and two `local_p` vectors and the two runtime body IDs. The fixed side is ID `-1` in world basis. The payload strips the native voxel pair, manifold identity and per-record substep, and truncates at 100. See `docs/research/PDD-Sable-2.0.6-Plot-Coordinate-Forensics.md:113–143`, `NativeCollisionTelemetry.java:106–111`, and the pinned Rust `clearCollisions` in that document. Sable's raw force scalar and callback target are independent of the signed normal. The current two Java paths only authorize orientations: `NativeEffectDirection.java:41–104,109–163,168–184` averages reported normals and separately checks pre/effect linear pose. `NativePlotDirection.java:60–124,279–372` checks the pair across retained substeps and projects to an axis. `RealFixRuntimeBridge.java:840–887` logs `exactContact=false deformationAuthorized=false`, then forwards the preview by owner alone. `DirectionEvidence.java:6–14` can encode exactly one signed axis. Neither path can be upgraded solely by renaming a quality label or by reading the preview.
- For an actual move, keep the approved same-Credit new-impact gate and issue a separate **target-bound** witness while the original batch is still available (`RealFixRuntimeBridge.java:396–425,466–485,707–711`). Reject `capSaturated`, missing/invalid/ambiguous frames, unaudited candidate geometry, contradictory normals, and any PDD capture loss for the source group. With `NativeContactMassEpoch.java:22–46,55–91`, require all observed same-tick preframes to match runtime ID, Plot UUID, COM and the supported unit scale. With `NativeEffectDirection.java:62–75,109–157`, require real opposing A/B normals and valid effect / each possible pre-frame basis. Preserve and check the individual inward vectors and signed step choices before representative averaging. The source-substep field remains `-1`. Existing `NativeApproachEvidence.java:15–44` can corroborate closing by pre-solver translation (positive in at least one frame, no contradictory separation). That is suitable for a conservative subset and does not establish rotation-only approach.
- Match each original native record's correct side to the seed using the same record's R2 point, actual owner, fingerprint and shape. `SableConsumerTargets.java:34–61,236–247` already provides conversion and ≤8 candidate cells, and `SableContactRegions.java:90–131` audits the actual same-record shape. `OwnerResolver.java:142–165,295–312` currently proves proximity to a collision-shape AABB, including interior points. Movement authorization requires directional geometry as well, for example a unique candidate near the exposed full-cube face consistent with that record's outward normal. For a verified oblique full-cube case, select the relevant outward face/edge normal cone and check the signed components and actual witness proximity for each retained axis. Keep the unit vector for IDS §7.7's X/Z/Y ties and 0.5 secondary-axis ratio. Distinguish an unresolved candidate and an air/occupied move obstruction. A shape-audited added patch (`SableContactRegions.java:134–190`) has extrapolated support and is insufficient as an original seed witness. A derived recipient needs a frozen owner-local path carrying the corroborated signed direction, whose actual matches and contributing parents agree. An owner-level aggregate alone supplies neither. This distinction preserves valid directed movement without claiming a raw solver manifold, exact native contact, or measured impulse.

## Actual mutation path

- **World.** `NeoForgeWorldGateway.java:38–61` already checks server thread, world bounds, `getChunkNow`, and rejects both allocated and reserved Plot chunks. Preserve that check on source, destination, and diagonal corridor, plus before-state/fingerprint/incarnation CAS. `canDamage` and `canBreak` at lines 70–105 use FakePlayer `mayInteract`/`mayBuild` and explicit `BreakEvent` for the latter. Neither grants destination placement/claims. Moving requires authorization for source removal and destination placement under the applicable claim contract. No current move hook was located. The supported operation is server-level `setBlock` on the exact destination state and setting the source to air without `destroyBlock`, with normal client/neighbor updates preserved. Ordinary supported full blocks can use this path with a check on both cells, entities/collision and `canSurvive`/support/neighbor constraints, plus no BE, fluids, gravity/linked/kinetic/glue dependencies. Full-cube geometry by itself proves none of those policies. `readIfLoaded` intentionally ignores stale block entities on an air cell to handle break readback. A move preflight must inspect the actual destination BE and fluid state independently.
- **Plot.** Reuse `NeoForgePlotGateway.java:78–104` to map both source and destination by live UUID/generation and container ownership, checking each allocated loaded chunk. The embedded setter and query take **center-relative** coordinates; permissions and allocated chunk APIs take the allocation-space position. `EmbeddedPlotLevelAccessor.setBlock(BlockPos,BlockState,int,int)` bytecode offsets by `center` at 0–11 and calls `Level.setBlock` at 16. `getEntities` also offsets a local AABB by the center. The API routes both writes through `LevelChunkMixin.sable$setBlockState` offsets 37–114 to `SableCommonEvents.handleBlockChange`, with `sable$postSetBlockState` forwarding `LevelPlot.onBlockChange`. `SableCommonEvents.handleBlockChange` offsets 61–86 update `PlotChunkHolder`, bounding box, and expansion, 100–182 handle water/floating controllers, and 185–228 call HeatMap added/removed. `SubLevelPhysicsSystem.handleBlockChange` offsets 107–145 invoke normal mass update and `PhysicsPipeline.handleBlockChange`, followed by wake-up. No direct mass/collider patches are needed or justified.
- Plot move also requires an idle HeatMap before editing, a final connected topology (or verified split lineage), and **a subsequent successful Sable HeatMap tick**, same generation, clean pending lists and verified post-state pair before final sparse relocation/receipt or further moves on that Plot. `SubLevelHeatMapManager.onSolidAdded` offsets 49–204 can change `removed`, `newStarts`, `floodfill`, or split state. `onSolidRemoved` offsets 0–21 immediately decrements `solidCount` and enqueues the removed cell. The existing break fence in `NeoForgePlotGateway.java:158–209` checks initialized/splitComplete/floodfill/removed/newStarts/split cells and tracks tick/owner spacing. `SablePlotTickWitnessMixin.java:14–26` stamps only after the real HeatMap call returns. `PhysicalDestroyDeform.java:98–126` already processes commit services at ServerTick Post. Avoid physics-step writes, a chunk creation side effect, or contact-driven overwrite of an unrelated owner. The live HeatMap observation is stronger than a fixed tick delay.
- No two-cell atomic primitive was found. Sable's public `SubLevelAssemblyHelper.moveBlocks(ServerLevel,AssemblyTransform,Iterable)` is intended for assembly. Its bytecode may create Plot chunks at 255–268 and alter placement handling at 283–288. Destination `LevelChunk.setBlockState` is at 529, source at 892. BE save/removal/load and assembly callbacks surround independent writes. This helper bypasses PDD's loaded-only, owner, precondition, permission and journal protocol if called as an atomic move. Both ordinary `setBlock` writes must be guarded as one journaled transaction, with a durably prepared two-cell before image, mutable-state and BE vetoes, exact before/after verification, rollback or quarantine on uncertainty and state-key/incarnation updates only on confirmed success. No success from two true booleans alone. Keep the move WAL distinct from a one-cell break frame unless the schema is extended for both cells. `WorldBlockReplacementMixin.java:20–30` reports each real write; `WorldCommitService.java:275–301` and `PlotCommitService.java:276–277` currently suppress a single owned break only. A move needs a two-cell scoped expected-mutation guard, and unrelated side effects still need normal invalidation. The existing Plot startup `PREPARED` break logic quarantines rather than proves two-cell completion (`PlotCommitService.java:296–306`).

## Glue and remaining blockers

- Create 6.0.10 `SuperGlueEntity.isGlued(LevelAccessor, BlockPos, Direction, Set<SuperGlueEntity>)` searches an inflated AABB and requires both cell centers to be contained (`javap` offsets 65–147). It takes coordinates matching the queried accessor. The Sable 2.0.6 Create compatibility mixin redirects `collectCropped` only and uses `SubLevelInclusiveLevelEntityGetter.getIgnoringSubLevels`; it does not change `isGlued`. Aeronautics 1.3.2 bundles Simulated 1.3.2, whose `HoneyGlueEntity.contains(BlockPos)` checks the AABB against the cell center. `SimEntityTypes` registers `honey_glue`. Consider both kinds at source and destination, and check involved neighbors and kinetic/multiblock dependencies separately. Existing Gradle (`build.gradle:31–43`) declares Sable common/companion and JUnit, not Create or Aeronautics. Direct imports of glue implementation classes require compile-classpath verification. Registry identification with a bounded owner-space entity query is possible without importing them. An absent or ambiguous entity query cannot prove that a Plot cell is unglued.
- World has a concrete supported per-cell write path for ordinary full blocks, but live movement authority, both-end claim permission, dependency/BE checks and the two-cell WAL remain necessary implementation work. Plot has verified standard hooks for mass/collider, but two independent writes can trigger observers; atomic recovery, connectivity/glue checks and the later clean lifecycle readback remain unresolved by the JAR declarations. The readback itself cannot demonstrate exact lineage after a split or confirm a crash-consistent move using only a surviving coordinate or fingerprint. Unverified direction is damage-only with reserved movement Q unused. Verified direction denied for independent space/safety reasons may use the original same-Credit blocked reserve under §7.7.1. A partially applied or uncertain move should never be turned into a confirmed denied move or an additional damage debit merely to clear the queue.
