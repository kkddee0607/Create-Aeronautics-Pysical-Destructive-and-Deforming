## 2. 기능 구현 및 불변식

### A. 검증된 사선 법선의 F 분배

1. Sable-native `local_n1/local_n2` → 소유자 로컬 inward 벡터는 기존 `NativeEffectDirection`/`FrameMath`의 실제 법선 및 pre/effect pose 증거로만 승격한다. **법선 성분은 반올림하지 않는다.** 좌표/회전/스케일 검증 불확실 시 `Orientation.UNKNOWN`.
2. ColFix3의 동일 Plot-local/World 좌표계 및 6면 인접, 전방 30° 원뿔, 후진 간선 금지, 각 부모/자식의 유효성 증명, 다중 시드 BFS 깊이/중복 방문 방지는 유지한다. 현재 서버 틱에서 이동하는 Plot의 월드 pose를 매 BFS 층마다 갱신하지 않는다.
3. 실제 유효한 자식이 있을 때 `outF=0.5 * parentIncomingF * t(E_parent)`을 먼저 계산한다. 검증된 법선 `n` 및 부모→자식 단위 격자 방향 `e`에 대하여 `score_i=max(0.01,max(0,n·e))`를 구한다. 이 점수는 가중치 산정 정책으로서 물리적 확률이 아니다.
4. 자식마다 1/10 최소 몫을 먼저 예약하고, 남은 `(10-childCount)`/10을 점수 비율로 나눈 뒤 최대잔여법으로 정수 십분율을 확정한다. 동점은 기존 6면 방향 순서대로 결정한다. 최종 가중치는 0.1의 배수, 합 1.0. 노드당 6면이므로 최소 0.1 예약이 항상 가능하다.
5. 자식별 실제 F는 `outF * weight_i`로 나누고 마지막 자식에 실수 잔차를 귀속시킨다. 자식 수신 F는 부모 기여 합. 각 고유 블록의 Q 변환은 딱 한 번. 정상 종단만 잔액 전량, 불확실 경계는 미해결 F. 기존 탄성 식·재료 수치·Q/할당 cap은 변경 없음.
6. `UNKNOWN` 법선에서는 가중치를 양자화하지 않고 `1/childCount` 균등 분배를 그대로 사용한다. 깊이 2 제한도 유지한다.

### B. 상세 추적 — 소스 원장 밖, 승인된 사건만

- `[PDD-F-EDGE]`: `credit`(pair/generation), owner, layer, parent, child, `parentReceivedF`, `parentLocalF`, `parentOutgoingF`(탄성 반영 후), `directionWeight`, 실제 `sentF`, `normalFrame=OWNER_LOCAL`, `normal`, `normalEvidence`.
- `[PDD-F-MERGE]`: 유일 자식의 `parentCount`, 부모들로부터 실제 합산한 `totalReceivedF`, `processedOnce`.
- `[PDD-F-TRACE]`: 전체 edge/receipt 개수, 실제 출력 줄 수, 생략 줄 수, 설정된 상한, 양자화 단위.
- 충돌 유효성·Q 상한 검증까지 통과해야 로그를 송출한다. 중복 사건, 잘못된 owner 및 실패한 발행에 대해서는 edge/merge 로그를 송출하지 않는다. 로그 콜백 실패도 승인된 충돌을 취소할 수 없다.
- 로그는 기본 ON(진단 릴리스)이며 `-Dpdd.f.trace.enabled=false`로 OFF. 틱당 128줄, 사건당 96줄(엣지/합류 합산). 상한 초과는 요약의 `suppressed`에 기록. **모든 내부 간선이 항상 로그로 출력되는 것은 아님**.
- 추적 이벤트는 임시 계산 중에만 수집하고 `ContactCreditLedger.Grant`나 체크포인트에 저장하지 않는다.

### C. 의도적으로 건드리지 않은 부분

- `MaterialRegistry.java`, 재료용 CSV/JSON, 경도·파괴 임계 T·연성·탄성 계수와 보강된 심층암 값 **미변경**. `MaterialRegistry.ALGORITHM_REVISION`, 기존 `GameImpactCredit.POLICY_REVISION`, `DamageModel.ALGORITHM_REVISION`은 실제 행위가 변경되지 않았으므로 ColFix3 값을 그대로 보존. F 분배 방식이 변경된 `ContactCreditLedger.ALGORITHM_REVISION`만 superFix로 갱신.
- Sable/NeoForge/Create/Aeronautics 버전 및 Gradle 의존성, 원본 콜백 반환·타이밍, World 변경, 폭발, 실제 파괴/변형 미변경.
- Preview checkpoint 파일 이름은 정책 변경으로 `pdd-0.4.0superFix-preview-only*.bin`으로 새 버전 격리. 이전 파일은 읽거나 덮어쓰지 않는다.

## 3. 외부 API 및 빌드·검증 상태

- 업로드된 `sable-neoforge-1.21.1-2.0.6.jar`의 클래스 선언을 `jar tf`/`javap`으로 확인: `ServerSubLevel#getPlot()`, `LevelPlot#getCenterBlock()` 존재. API를 새로 호출하는 코드는 추가하지 않았다.
- 기존 클래스패스는 `build.gradle` 그대로: NeoForge ModDev, Java 21, Sable developer API 및 Sable Companion, JUnit 5.11.4. **실제 classpath dependency resolution은 미검증**(Gradle Wrapper/네트워크 미제공).
- **실제 독립 Java 21 컴파일 성공:** `DamageModel`, `MaterialProperties`, `BlockDamageState`, `ImpactSample`, `FrameMath`, `GameImpactCredit`, `ForcePropagation`, `ContactCreditLedger`, `SparseStateKey`, `SparseDamageState`, `SparseStateCodec`, `PreviewCheckpoint`.
- **독립 체크 35/35 성공:** 본 릴리스 신규 가중치/합류 5건, 승인 원장/추적 3건, 기존 ColFix3 방향성 5건, 기존 ColFix2 회귀 9건, `ContactCreditLedgerTest` 11건, `PreviewCheckpointTest` 2건. `org.junit.jupiter.api` 임시 어노테이션/Assertion 스텁 + 독립 리플렉션 러너로 실행한 것이며 **공식 JUnit 5 실행 성공으로 주장하지 않음**.
- `RealFixRuntimeBridge`/NeoForge 소스 전체는 정적으로 검토했으나 실제 Minecraft/NeoForge 전체 클래스패스 컴파일 미실행.
- `compileJava`: 공식 Gradle 미실행; `compileTestJava`: 공식 Gradle 미실행; `processResources`: 미실행; `jar`: 미실행; `clean test`: 미실행; `build`: 미실행; GitHub Actions: 미실행; 인게임: 미실행.
- 종단·F 회계 검증: `assignedF + dampedF + unresolvedF == inputF` (부동소수 허용오차), `candidateQ == finalQ + dampedQ`, 유일 좌표별 1회 Q, 실제 edge 기여합 = child receipt 합. 테스트한 범위에서 정적 오류 미발견. 완전한 외부 라이브러리/런타임 컴파일 증명 아님.

## 4. 최대 두 번의 사용자 인게임 테스트

**1회 — 사선(30°–45°) 법선과 균등/비균등 분배:** 2×2 이상의 면 연결 Plot 구조체를 회전시켜 정적 계단 벽에 비스듬하게 충돌시킨다. 접촉 이전 실제 분리·접근을 확보해야 승인됨. `[PDD-NATIVE-NORMAL] status=CORROBORATED`의 서로 다른 축 성분이 있는 방향을 선택하고 `[PDD-F-EDGE]`의 동일 부모에게서 나간 `directionWeight`를 확인한다. 승인됐어도 법선이 `UNKNOWN`이면 균등 fallback으로 구분하며 **이 테스트의 사선 성공으로 판정하지 않음**. 합격: 자식 가중치가 0.1의 배수, 합 1.0, 자식 `sentF` 합 = 부모 `parentOutgoingF`, 역방향 간선 없음, `PDD-F-LEDGER` 잔액 정합.

**2회 — 다중 부모 합류:** 2×2 다이아몬드형 6면 연결 격자(접촉 `(0,0,0)`에서 `(1,0,0)` 및 `(0,0,1)`을 거쳐 `(1,0,1)`로 합류)를 가진 Plot을 실제 충돌에 사용한다. 전파 가능 각도 및 검증된 owner-local normal이 두 경로를 허용해야 함. `[PDD-F-MERGE] child=(1,0,1) parentCount=2`면 각 `[PDD-F-EDGE]`의 `sentF` 합과 `totalReceivedF`를 비교하고, 같은 자식의 피해 계획이 1건인지 확인한다. 합류 경로가 실제로 열리지 않았다면 미검증이지 반드시 오류는 아님.

**오류 보고:** `latest.log`에서 `PDD-NATIVE-NORMAL`, `PDD-F-EDGE`, `PDD-F-MERGE`, `PDD-F-TRACE`, `PDD-F-LEDGER`, `PDD-F-PROPAGATION`, `PDD-MATERIAL-PLAN`, `PDD-EPISODE`, 최초 Exception 스택을 함께 제출한다. 출력 예산이 부족하면 `PDD-F-TRACE suppressed > 0`을 먼저 확인한다. `worldMutation=OFF`라 블록이 부서지거나 손상이 반영되는 모습을 성공 기준으로 삼지 않는다.
