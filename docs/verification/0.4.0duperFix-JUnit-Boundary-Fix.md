# PDD 0.4.0duperFix — JUnit boundary regression fix

## Basis

- GitHub `main` commit: `c36aad9babe924ef65d754633fa4e5dd740fb445`.
- Original 175-file Apply-eligible tree was byte-for-byte identical to the previously released `PDD-0.4.0duperFix-FULL-SOURCE-APPLY.zip` (path + Git blob SHA manifest checksum `26184cbc`).
- User-provided GitHub Actions `./gradlew test --no-daemon` completed `compileJava`, `processResources`, `compileTestJava` but **failed one assertion** of 303 executed tests: `ForcePropagationTest.boundedGraphNeverPassesLeftoverForceToArbitraryLastNode`, line 124.

## Root cause (test fixture, not confirmed production failure)

DuperFix raised `ForcePropagation.MAX_NODES_PER_SIDE` from 128 to 2,048 to support larger Plot/World geometry. The existing test created a **200-node straight line** but still expected to hit `MAX_NODES_PER_SIDE` and finish at `UNVERIFIED_BOUNDARY`. The new cap exceeds its graph size: with the synthetic F `1e70`, the algorithm reaches a **verified terminal** and legitimately consumes the remainder. The original assertion was therefore obsolete; reducing the cap or faking an unsafe boundary would regress the new propagation policy.

## Changes

- `src/test/java/com/physicaldestroydeform/collision/ForcePropagationTest.java` only: retain `boundedGraphNeverPassesLeftoverForceToArbitraryLastNode` and all four existing assertions. Build its graph as a dense, fully connected square with width `ceil(sqrt(MAX_NODES_PER_SIDE)) + 2`, so its size exceeds the current node-work cap without prematurely triggering a depth/F floor. The original test continues to verify the **safety boundary and F preservation**.
- Add `twoHundredConnectedBlocksNowReachVerifiedTerminalUnderExpandedBudget`: preserve the original 200-block case as an explicit **verified terminal, no unresolved F** test.
- No production Java code, resource, mod metadata, Gradle settings, version, material profiles, callback or runtime diagnostic changed.
