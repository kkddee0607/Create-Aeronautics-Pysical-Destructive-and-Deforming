## API 및 정확도 구분

- 실제 첨부된 Sable 2.0.6 JAR 정적 바이트코드 검사: `Rapier3D.clearCollisions(J)[D`, `ServerSubLevel.boundingBox():BoundingBox3dc`, `SubLevelContainer.getContainer(ServerLevel)`, `ServerSubLevelContainer.getAllSubLevels()` 및 Companion `BoundingBox3dc` accessor. Java 21 실제 모의 타입체크는 정식 compileClasspath 검사가 아니다.
- R1은 기존 Sable 원본 nonnull callback에 대해 실제 검증 가능한 경우에만 승인한다. R2/R3 collider-relative transform은 아직 실제 충돌 프레임으로 교정되지 않았고, R4는 제한 탐색한 후보를 `PROVISIONAL_ONLY`로 유지한다. 원본 callback이 null인 일반 블록은 target 검증이 실패하여 `Q=0`일 수 있다. **G-TARGET-01의 일반 World↔Plot/회전 커버리지는 아직 입증되지 않았으며 정확한 게임 기능 완료를 선언하지 않는다.**
- AABB 겹침/사후 force/정지 시간/콜백 부재는 독립적인 충돌 시작 증거가 아님. 실제 분리와 접근, 최소 하나의 검증된 local target, 중복 장부를 요구하며, 정보 부족 시 Q=0.
- 원본 Sable/JNI 배열·callback 부수효과·물리 상태는 수정하지 않으며 다른 모드의 JAR은 ZIP에 포함하지 않는다.

## 두 번의 인게임 검증 (GitHub Build 성공 이후)

### 세션 1: World↔Plot / 초기 충돌·실제 분리·재충돌 / 원본 콜백

1. Minecraft 1.21.1 / NeoForge 21.1.228 / Sable 2.0.6 / Create 6.0.10 / Aeronautics 1.3.2에서 빌드한 realFix JAR 한 개만 설치한다. 기존 moreRog JAR은 제거한다. 추가 JVM 플래그는 필요하지 않아야 한다.
2. 석재 Plot을 정적 석재 벽에 충돌시킨다. 첫 충돌 이후 충분히 분리된 두 번 이상의 물리 샘플을 관측하고 다시 충돌시킨다. Belt/Fragile 등 원본 특수 콜백도 PDD OFF와 비교한다.
3. 기대 로그: `[PDD-OBS] source=POST_EFFECT ... bodyIds=... rawRecords=... peakForce=...`, `[PDD-TARGET] ... ownerAGeneration=... frameMethod=R1_OR_NONE ... targetA/B ... reason=...`, `[PDD-EPISODE] ... previousSeparated=... forceRise=... creditCount=... Q=... worldMutation=OFF`. R4는 `PROVISIONAL_ONLY`, 검증 미확보 시 Q=0이 정상 fail-closed이고 **타깃 커버리지 합격이 아님**.
4. 확인: 실제 dimension/Plot UUID/BlockPos와 일치, Sable 원본 callback 횟수·리턴/예외 동일, 신규 타격 한 번만 Q>0 (필요한 충분한 근거가 있을 때), world block 변경 없음. 충돌 관측 0건이면 G-OBS FAIL, 잘못된 블록이면 G-TARGET FAIL.

### 세션 2: Plot↔Plot / 회전-only / 다중 접촉 / 정지 접촉

1. 별도의 Plot 두 개로 서로 충돌시킨다. 한쪽을 90도 회전하고 회전-only 충돌도 일으킨다. 약 20틱 접촉 정지→실제 분리≥2 샘플→재충돌과 동시에 여러 면 충돌을 시험한다.
2. `PDD-OBS`의 pair/tick 최대 force가 contact point 합계가 아닌지 확인한다. `[PDD-EPISODE]`의 동일 episode 중복 Q=0, 분리·접근 후 한 번만 후보 Q가 발생하는지 확인한다. 원본 물리/CCD/특수 콜백 불변 확인.
3. nativeMalformed=0, nativeDropped=0, callbackDropped=0, preHistoryDropped=0, 예외/크래시=0, worldMutation=OFF 확인. 타깃 불명확하면 `TARGET_UNVERIFIED` Q=0이어야 한다. 타깃 검증을 끝내지 못했으면 **G-TARGET 미합격을 그대로 보고**하고 임의 PASS 처리하지 않는다.

## 배포·Apply 전달

1. 저장소 `incoming/`에 존재하는 구형 `PDD-0.3.0realFix-GitHub-Source-Integration-Kit-NOT-APPLY.zip`을 먼저 제거한다. `incoming/*.zip`은 반드시 정확히 하나여야 한다.
2. 새 `PDD-0.3.0realFix-FULL-SOURCE-UNVERIFIED-APPLY.zip` 하나만 업로드. 사용자 직접 Apply 실행/작업 결과 확인.
3. Apply는 zip 내부 단일 Gradle 프로젝트를 탐색하고 모든 비보호 항목을 동기화한다. ZIP에서 제외한 `.github/`, `incoming/`, `gradlew`, `gradlew.bat`, `gradle/`은 GitHub 원본이 보호·유지한다. ZIP이 새 workflow/JAR를 직접 배포하는 것은 아니다.
4. 변경 커밋에서 전체 소스 확인 후 Gradle Build와 Callback Test 실행. 실패하면 첫 오류를 근거로 소스 수정 후 전체 `clean test`, `build` 재실행하고, 인게임 검증 후에만 정식 완료 선언한다.
