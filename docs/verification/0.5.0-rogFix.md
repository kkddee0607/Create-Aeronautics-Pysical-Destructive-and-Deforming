# PDD 0.5.0-rogFix — World Persistence Recovery Audit

Baseline: `main` commit `3d7a2493c6237496c3a44b6341f872f628311009` and verified
0.5.0-moreFix k=0.1 + SELF-ELASTIC-90 complete source. Design: IDS 1.0.7
§14.1, §24.3, §31, G-SAVE-01. No native physics, F/Q, damage, stress or
contact-face algorithm was changed.

## Root cause and safety contract

The previous boot reconciliation treated every persisted `DEFERRED` receipt as
potentially mutating a Minecraft block and terminally recorded it as
`PARTIAL_QUARANTINED`. But `WorldCommitCore.apply()` only invokes vanilla
`breakVanillaOnce()` **after** persisting a separate `PREPARED` receipt. A
`DEFERRED` record is queued; its sealed Q/material payload is **not** persisted.
Re-running it after restart would invent a plan. Mark it durably **ABORTED**
with reason `RESTART_DEFERRED_NOT_EXECUTED_INTENT_NOT_PERSISTED`; do not reissue
Q, mutate the world, or force-load a chunk. Report this lost/unapplied intent.

A persisted `PREPARED` receipt is different: Minecraft mutation may have
occurred before a crash. Wait for an already-loaded chunk and then record
`PARTIAL_QUARANTINED` with the observed AIR/PRESENT state. It remains blocked
from replay and explicitly requires operator inspection. A null/unloaded
observation is **not** evidence for a terminal decision.

The previous moreFix runtime already stored a number of incorrect terminal
receipts with `PARTIAL_QUARANTINED`, reason
`RESTART_UNCERTAIN_DEFERRED_...`. These IDs must stay terminal (never replay),
but, because their previous status was explicitly DEFERRED, they do **not**
prove an ambiguous vanilla mutation. At startup, PDD recognizes this exact
legacy reason and does not unnecessarily quarantine the corresponding block
cell. All other terminal `PARTIAL_QUARANTINED` receipts are re-established as
protected cells, including earlier truly uncertain PREPARED/break failures.
No receipt is rewritten to erase a safety record.

## Instrumentation

* `[PDD-RECOVERY] phase=HISTORICAL_QUARANTINE`: previous terminal partials,
  proven legacy unexecuted deferred records, and genuinely uncertain cells.
* `[PDD-RECOVERY] phase=START`: current boot pending DEFERRED/PREPARED counts
  and explicit no-replay policy.
* `[PDD-RECOVERY] phase=RESOLVE`: receipt ID, original status, durable result,
  reason, observed block fingerprint, manual-repair classification, unknown Q.
  Only the first four records are emitted by default; set the **optional**
  `-Dpdd.persistence.traceRecovery=true` for all IDs during focused diagnosis.
* `[PDD-RECOVERY] phase=SUMMARY` (100 ticks): cumulative statuses, waiting
  loaded-chunk work and failed lookup attempts.
* `[PDD-RECOVERY] phase=STOP`: shutdown record of resolved/waiting recovery.
* `[PDD-SAVE] phase=STOP`: now reports both live `pending` and
  `restorePending` explicitly; `CLEAN` alone never proves no work was lost.
* `[PDD-PERSIST]`: existing shard checkpoint, WAL tail repair, CRC and
  fail-closed messages retained; storage status adds `recoveredPending`.

Optimization: boot reconciliation is bounded by **8 receipts per server tick**
and a 2 ms *soft* pass deadline; each durable transition still performs its
required WAL fsync, so this is not a strict per-call latency guarantee.
`DEFERRED` does **not** request a redundant chunk read; no global scan or
extra dependency was introduced. Per-receipt default logging is rate-limited.

## Existing gameplay contracts preserved

* Sable callback return and contact event sequencing unchanged.
* k=`0.1`, maxGameF=`40,000,000`, default Qmax=`3,999,999.8` unchanged.
* T1024, self-elasticity `SELF-ELASTIC-90`, F/Q transfer, deformation-preview,
  world owner checks, block CAS, break/drop contract unchanged.
* Recovery does not recompute damage, redistribute Q or create new credit.
* Native/world mutation is not performed during boot reconciliation.
* Persisted schema remains 2; no destructive migration, no state reset.

## Independent checks (NOT official JUnit/NeoForge)

Java 21 compiled the relevant production World journal, commit core and
`WorldCommitService` (the latter with stand-in Minecraft/SLF4J types). 33
World persistence/commit test methods and 21 damage/material test methods ran
through a temporary JUnit-compatible assertion runner: **54 passed**.
In addition, the unchanged standalone WorldCommitCore and WorldIntentMapper
self-checks exercised 44 and 10 assertions respectively. Full Gradle/JUnit,
NeoForge compilation, GitHub Actions, and in-game results are NOT verified here.

Two integration tests added: restarting a queued DEFERRED without loading a
chunk must end ABORTED without a break, and a PREPARED record must stay pending
until the chunk is loaded and then quarantine without a second break. Legacy
false quarantine classification has a separate test. Existing checkpoint I/O
failure test was updated to wait across bounded checkpoint batches rather than
incorrectly assuming that the first 2 ms pass must write every shard.

## Two in-game test sessions

1. **Existing-world, non-destructive restart**: Back up the world **and**
   `data/pdd-world-0.5.0/` before updating. Start and inspect
   `HISTORICAL_QUARANTINE` and `START`. Previous `RESTART_UNCERTAIN_DEFERRED_*`
   receipts should appear under `provenNeverExecutedDeferred`; they must not
   cause 2,334 new per-ID manual repair warnings. Check `SUMMARY`/`STOP` for
   `awaitingLoaded`, `deferredAborted`, `preparedQuarantined`. If any true
   PREPARED quarantine persists, preserve the save and submit its receipt ID.
2. **Normal collisions and repeated save/restart**: Repeat the known-working
   small- and large-Plot collisions into loaded static World blocks. Observe
   the same F/Q caps, damage and break results, then close and reopen.
   `PDD-F-INVARIANT` should remain PASS and blocks must not rebreak or drop
   again merely because the server restarted. The second boot must not
   reproduce terminal-deferred manual quarantine logs. Report `PDD-RECOVERY`,
   `PDD-PERSIST`, `PDD-SAVE`, `PDD-COMMIT` and any stack traces if unexpected.

**Remaining limitations:** A crash after PREPARED cannot be conclusively
resolved from only current AIR/PRESENT status; automatic exactly-once block
break+drop recovery is not claimed. A DEFERRED receipt lacks the serialized
original Q/material snapshot, so recovery must abort it rather than replay it.
If an already terminal unknown partial receipt exists on a position, that
position remains conservatively guarded until verified replacement.
