## Fixes and why they are safe

1. **Duplicate native-cell block lookups** — `OwnerResolver.NativeAuditBatch` holds only a per-native-**group** map of `(ownerKey, allocatedBlockPos)` to the validated live block identity and collision shape. `SableContactRegions.audit` now charges its 32-check-per-side quota for **new** owner/cell lookups rather than each repeated source point. Every source point still runs `nearShape(shape, point, allocatedPos)` independently, including cache hits. A previous point's shape-match verdict is **never cached** for a different point. This keeps the same validation tolerance, loaded-chunk and owner checks while suppressing repeated expensive reads. Cache is discarded after one group; no cross-tick stale owner data is reused.
2. **One-side target overflow** — when a side acquires >4 *verified distinct* targets, that entire side is **quarantined** (not reduced to an arbitrarily chosen four). It is no longer inspected within that group; all its Q share remains **unused**. The other side may still be fully audited and receive only its own verified share, provided the entire remaining scan completes. If both sides overflow or any required surviving side's scan is incomplete, Q=0. Trace records `TARGET_LIMIT_A/B`, exceeded count and which side was quarantined. Never expand the configured target limit to mask a conflict.
3. **Excessive source-region combinations** — when more than 16 per-record region pairs result despite ≤4 real blocks per side, the evidence is compacted into at most eight **single-side** regions built only from independently verified targets. This avoids inventing contact pairs; the existing single source-group Q is distributed once. A single record with genuinely excessive targets is still quarantined as above.
4. **R3 budget accounting** — use the exact remaining group budget instead of pessimistically reserving all eight candidate checks. A valid one-cell R3 candidate can be audited with one remaining check; if the bounded R3 scan runs out, return an incomplete result without approving its partial target. Do not clip actual check counts or exceed 32 unique checks per side. Incomplete source groups fail closed. The R4 swept-world path remains provisional, not credit authority.
5. **Coordinate/frame diagnostic** — `SableConsumerTargets.frameResidual` reports independently reconstructed world points, their difference vector and magnitude, and whether either frame/scale is unavailable. On first uncorroborated record, `[PDD-FIX-FRAME]` prints the *actual failed source ordinal*, raw collider-local points, the associated actual effect-phase frames, reconstructed world points, residual, and the unchanged 0.25 block threshold. It is sampled at the existing verification logger frequency. This is evidence for a later correction, not a guessed collider transform or relaxed threshold.

## Testing and acceptance (maximum two in-game sessions)

**Prerequisites:** Build and Callback Contract GitHub Actions pass; runtime Minecraft Java 1.21.1, NeoForge 21.1.x, Create 6.0.10, Aeronautics 1.3.2, Sable 2.0.6. Confirm loaded PDD is **0.3.1fix**, source `SABLE_ORIGINAL_POST_EFFECT`, `mutation=OFF`; old `0.3.1verf` JAR must not remain in `mods/`.

**Session 1:** B1 flail against stationary A1 stone wall, then A2 grass ground. For each, begin separated, strike, hold without withdrawing, separate for ≥2 stable ticks, strike again. Capture full `latest.log` from world start. Verify actual world BlockPos matches `PDD-LEDGER` and no extra Q appears during sustained contact.

**Session 2:** B1 vs B2 balloon Plot, then B1 vs B3 stone-wall Plot. Repeat initial strike, sustained touch and verified withdrawal/restrike. Include corner/edge and larger face contacts to reproduce formerly excessive candidate counts. Record visually contacted Plot-local blocks when possible; collect full log.

**Pass criteria:** one source group issues ≤64 Q once per valid independent episode; Q allocated A+B+unused equals issued Q; verified targets belong to correct owner and real loaded shape; repeated cell lookups no longer spend 32 checks repeatedly; >4-target side never receives partial arbitrary Q; other side receives at most its own verified share; `R4` never authorizes Q; mismatched world points remain unverified with explicit residual; original callbacks behave unchanged; no observer errors and no world mutation. **No claim that every TOO_BROAD or coordinate mismatch is fixed:** genuinely broad contacts and missing collider-frame evidence still fail closed and are expected to be diagnosed.

**Failure report:** ZIP Apply log, Gradle Build and Callback Contract Actions logs if failed, and `latest.log` including `PDD-FIX-FRAME`, `PDD-VERF-REGION`, `PDD-VERF-FSM`, `PDD-LEDGER`, full context. Note trial B1↔A1/A2/B2/B3, impact location and any visual discrepancy. `original contact ordinal` is NOT a stable solver manifold ID.
