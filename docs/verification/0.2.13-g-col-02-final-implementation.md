## Corrected root causes

1. **Wrong owner frame:** Each Sable hit-side callback's position must only be interpreted in the hit block's own space. Keep raw plot-local coordinates; project via that plot's frozen pre-solver pose to world. The other target is obtained by inverse-projecting that *world point*, not by projecting the raw point through the other plot's pose.
2. **Impossible raw plot positions:** The earlier implementation returned `DIAGNOSTIC_ONLY` even for plot blocks whose native raw contact point was a placeholder world coordinate or a value ~2,048 blocks from the reported owner. The new code rejects these with `INVALID / CONTACT_OUTSIDE_OWNER_BOUNDS` and never passes them as resolved contact geometry. A conservative 2-block block-shape margin is used, not a synthetic guessed coordinate replacement.
3. **No independent confirmation:** The previous adjacent-pair counters did not mark observations validated and generated spurious `mismatchedPairs`. New per-server-tick, spatially indexed reciprocal matching uses identical epoch/dimension/tick, exact reversed `BlockTarget` values and independent world points within 0.25 blocks. Successful matches become `PRE_SOLVER_VALIDATED` **before** `RawObservationDispatcher.dispatch`.
4. **Unlabelled validity:** The `RawObservation` remains byte-for-byte faithful to raw hit, other, position, signedVelocity and original response. Its source frame label starts as `HIT_PLOT_LOCAL_CANDIDATE`/`HIT_STATIC_WORLD_CANDIDATE` and becomes `_VALIDATED` only on an independent reciprocal match; otherwise invalid and unpaired observations do not get a validated label.
5. **Log amplification:** Detailed entries remain capped to a matched pair, an invalid example and one native effect sample per 100 server ticks. All counts continue, independent of debug verbosity.

## In-game validation — maximum two sessions

**Session 1: one plot against static world terrain**

1. Assemble a small physical plot; collide its hull with a stone wall at low then moderate speed, including a rotated contact.
2. Search `latest.log` for `[PDD-G-COL-02] phase=SUMMARY`, `PRE_SOLVER_VALIDATED`, `frameValidation=RECIPROCAL_MATCH`, and `HIT_PLOT_LOCAL_VALIDATED`.
3. Verify `validatedPairs` / `worldPlotPairs` increase; the two opposite-side `worldFromHit` points should be within 0.25 blocks of one another and the actual wall contact. Observe `invalidContacts` only for genuinely nonsensical raw shapes; the game and Sable's original physics must continue working unchanged.

**Session 2: two separately assembled plots**

1. Arrange two independently assembled ships, one rotated, then cause a contact.
2. Confirm both `stablePlotId` values differ, with no world-space coordinates accidentally used as plot-local impact points. `plotPlotPairs` should increase when Sable emits a pair of geometrically valid independent callbacks; `CONTACT_OUTSIDE_OWNER_BOUNDS` is an expected **safe rejection** for the known placeholder-callback case. An invalid sample must not be promoted or mutate a world block.
3. Save the two `latest.log` files. `G-COL-02` acceptance remains **NOT_RUN** until evaluated from those logs and corresponding in-game contact locations. Do not confuse individual `PRE_SOLVER_VALIDATED` events with passing the complete game-level gate.

**Remaining risk:** Sable native callbacks for specific original blocks (e.g., belt/rope) can expose nonphysical placeholder contact values; the correct 0.2.13 response is to reject them. Reconstructing such missing contacts from native effect vectors would require an independently verified ABI and must not be guessed. Gradle/CI and real game behavior remain unverified for the new archive.
