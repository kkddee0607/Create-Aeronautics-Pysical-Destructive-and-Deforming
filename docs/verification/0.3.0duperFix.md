## 2. 실제 superFix 테스트 로그로 확정한 결함과 경계

사용자 입력 장면: A1=정적 돌벽, A2=정적 잔디, B1=부유석 손잡이+사슬/보강된 심층암 추를 로프로 묶은 Plot, B2=열기구 기낭+버너/사슬/보강된 심층암 추 Plot. 순서대로 B1→A1, B1→A2, B1→B2.

- 제공된 `latestlog.txt`에 `PDD-EPISODE` 381개, `APPROVED` 5개, `DUPLICATE_EPISODE` 278개, `TARGET_UNVERIFIED` 57개, `APPROACH_UNVERIFIED` 37개, `INITIAL_CONTACT_UNKNOWN` 4개가 나타났다. 마지막 주기 집계는 `observed=343, credited=5, zero=338, targetMissing=288, r2Verified=57, r3Verified=25`이다. **집계 주기와 파일 전체 사건 수는 서로 다른 모수다.**
- 실제 블록 식별 사례: 정적 `minecraft:stone`, `minecraft:grass_block`; Plot `minecraft:reinforced_deepslate`, `minecraft:chain`, `aeronautics:levitite`. 숫자가 같은 Plot 내부 좌표와 월드 좌표를 혼합하면 안 된다.
- `CONTACT_FRAME_UNCORROBORATED`와 `MULTIPLE_BLOCKS`/`TOO_MANY_CANDIDATES`가 반복. **동일 소유자·틱의 모든 native contact를 먼저 합산한 뒤 검사하던 구현**은 개별 유효 접촉도 전체 배치의 다른 불일치 때문에 탈락시키고, 다른 접점의 point를 교차해 잘못 검증할 위험이 있었다.
- R4 `MULTIPLE_CONTACT_REGIONS`는 서로 다른 접촉점이 존재한다는 사실 자체를 실패 취급했다. 여러 접촉 후보를 승인할 근거는 아니지만, **진단상 유한한 합집합을 만들어 검사할 수 있다**.
- `Q=64` 포화는 §23의 `min(64,0.25*max(0,F_peak−2))`에 부합한다. 프로필을 임의 변경하지 않았다.
- `previousSeparated=false`와 `APPROVED`의 동시 출력은 과거의 `ARMED` 증거 때문일 수 있으며 단독 결함으로 단정하지 않는다. 반대로, 최근 2틱 밖의 실제 분리 증거가 있으면 처음 force event에서 `ARMED` 진입 이유를 보존해야 한다.

## 3. duperFix에서 실제 변경한 코드

1. **`collision/SableConsumerTargets.java`** — R2·R3의 각 native contact record를 독립적으로 양측 world-point 일치 확인 및 해당 record의 owner-local voxel/`VoxelShape`로 감사한다. 서로 다른 record의 접점을 교차 대조하여 가짜 block match를 생성하지 않는다. 검증되지 않은 record는 건너뛰되, 검증된 target이 둘 이상이면 `MULTIPLE_BLOCKS`로 거절한다. 동일 좌표+동일 접점의 중복 감사 결과는 캐시한다. 최대 8후보/point, 최대 32 실검사/owner-pair/tick, 초과하면 fail-closed. 부분 유효 출처는 `R2..._PARTIAL`/`R3..._PARTIAL`로 구분한다. **R2는 consumer-correlated GAME proxy이지 solver-native 정확도 보증이 아니다.**
2. **`collision/RealFixBoundaryCandidates.java`** — 다중 native world-contact point의 제한된 `nearContactPoints()` 합집합을 생성한다. 중복 블록 제거, 32 후보/owner 및 남은 틱 검사용량 준수. 단일 결과여도 `TARGET_INFERRED_PROVISIONAL` 이상으로 승격하지 않는다.
3. **`collision/RealFixBoundsEvidence.java`** — 이전/현재 world-space broad-phase AABB의 유한 swept union을 제공한다. R4 진단 범위를 위해서만 사용하며 world block 접촉 증명으로 사용하지 않는다.
4. **`collision/RealFixRuntimeBridge.java`** — R4의 즉시 `MULTIPLE_CONTACT_REGIONS` 종료를 제거하고 narrow swept-boundary 후보를 검사한다. 신규 충돌 판정에서는 `Phase.ARMED`이면서 **직전 contact 뒤에 실제로 관측된 separation**을 최근 2틱보다 오래된 경우에도 독립 접근 증거로 허용한다. 일반 `UNKNOWN`, 지속 접촉, 임의 quiet tick은 여전히 separation으로 취급하지 않는다. `phaseBefore`, `separationEvidenceTick`, `armedFromGap`, `aabbClosing`, `recentGap` 로그 추가. `approachByAabb` 진단은 AABB로 증명한 경우에만 true.
5. **`collision/GameImpactCredit.java`** — 기존 1회 group credit/FSM 구조를 보존하고, 읽기 전용 `phase(Pair)` 조회만 추가했다. `Qmax`, half-share/unused 및 동일 사건 중복 차단은 유지한다.
6. **`src/test` 3파일** — 레코드별 타깃 합의·모호성, R4 다중 지역 중복 제거 및 swept-boundary, 오래된 분리 증거 후 재타격을 검증한다. 기존 테스트를 삭제/비활성화하지 않았다.
7. 버전 태그·시작/종료 로그·Gradle `version`·JAR manifest·NeoForge mods.toml을 `0.3.0duperFix`로 조정했다. 기존 Gradle/NeoForge/JUnit 의존성 버전은 보존했다.

## 6. 인게임 두 세션 검증

사전 조건: GitHub `incoming/`에 해당 ZIP **1개**만 업로드 → 사용자가 Apply Action 실행 → Build 및 Callback Contract Test 확인 → 생성된 JAR을 `mods`에 설치(기존 PDD 중복 제거). MC 1.21.1/NeoForge 21.1.x/Java 21/Sable 2.0.6/Create 6.0.10/Aeronautics 1.3.2. `worldMutation=OFF` 유지. 기존 `-Dpdd.proxy.*` 등 오래된 JVM 옵션 미설정.

**세션 1: B1→A1 돌벽, B1→A2 잔디** — 실제로 타격된 돌벽/잔디 및 추/사슬 블록을 기억하거나 스크린샷 기록. B1을 벽에서 완전히 떼고, 일정 시간 후 수직 충돌 → 지속 접촉 20틱 → 분리 2틱 이상 → 동일 타깃 재충돌. 잔디에도 같은 절차. `PDD-NATIVE-TARGET`의 `reasonA/B`, `checkedA/B`, R2/R3 `_PARTIAL`, `PDD-TARGET`의 Plot relative / static world absolute target, `PDD-EPISODE`의 `phaseBefore`, `armedFromGap`, `separationEvidenceTick`, `APPROVED`, `Q`, `DUPLICATE_EPISODE`를 확인. 한 신규 사건에 **1회** Q, 유지 접촉에서는 0, 대상 불명확시 0, 기존 Sable 반발 정상이어야 합격.

**세션 2: B1→B2 (서로 다른 UUID의 회전 Plot)** — 로프/추/열기구 부품 중 실제 접촉 위치 확인. 서로 다른 Plot를 분리·대기·접촉·정지·재분리 후 재접촉. 회전/면/모서리/다중 접촉일 때 타깃 로그의 block registry ID·각 Plot 중심 상대좌표 확인. 유일 증거가 없는 `MULTIPLE_BLOCKS`/`TOO_MANY_CANDIDATES`는 Q=0, 하나만 검증되면 해당 측 절반을 사용할 뿐 다른 측을 추측하지 않음. `Q` 이중 발행, 잘못된 UUID/좌표 또는 Sable 반발 변화가 있으면 실패.

문제 발생 시 **전체 `latest.log`**, 사용자별 테스트 시작·종료 대략 시각, 실제 충돌한 블록(추/사슬/손잡이/기낭/버너), Actions Build/Callback 오류 로그(실패 시)를 제출. `worldMutation=OFF`라서 블록 파괴가 일어나지 않는 것은 정상이다.

## 7. 남은 제한 및 다음 버전과의 구분

- 이번 버전은 *더 많은 타깃을 무조건 통과시키는 버전이 아니다.* 원본 local point의 collider pose가 불분명하거나 복수 블록을 실제로 확인한 사건은 여전히 Q=0일 수 있다. 임의 단일 타깃 선택과 threshold 완화 금지.
- Native force scalar의 단위는 게임 proxy이며 물리 임펄스/줄(J)로 표기하지 않는다. `Q=64` 상한은 설계 그대로 유지했다.
- Sable callback null→non-null 변경, world mutation, 실제 변형, 응력, 네이티브 확장, 다중 타깃 예산 분배는 추가하지 않았다. §14에 따르면 다중 타깃 원장은 0.3.1 이후 과제다.
- **최종 상태:** 소스 수정·보조 검증·배포용 전체 비보호 소스 ZIP 구성 완료. 공식 Gradle/JUnit, GitHub Actions 및 인게임 검증은 사용자 확인 대기.
