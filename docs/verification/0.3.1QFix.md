## Changes

1. New pure-Java `collision/WorldClearanceVerifier.java`: independent, finite World grid clearance scan; at most 256 cells/pair/tick and 1,024 incremental checks globally per tick. Exactly the inflated AABB cell range is inspected, never merely the previously hit static block. Pending observations are scoped by canonical pair+generation and their grid cell footprint; changes restart the scan. A new Sable Native contact discards pending evidence.
2. **Freshness rule:** Results gathered across ticks only produce `IN_PROGRESS`. Upon completion, the full candidate region must be rechecked on a **single server tick**, subject to a separate 8,192 global confirmation budget. A changed World cell or unloaded chunk discovered during final confirmation returns BLOCKED/UNAVAILABLE; earlier snapshots are never implicitly trusted as evidence. Greater than 8,192 candidate cells returns TOO_BROAD. This deliberate ceiling prevents unbounded game-tick stalls.
3. `RealFixRuntimeBridge.java` and `GameImpactCredit.java`: use the new verifier both for already-tracked Plot↔World rearm and independent pre-contact arming; break the consecutive clearance streak when the intervening scan is unproved, without changing the original Q calculation or ledger contract. Explicit `[PDD-WORLD-CLEARANCE]` status/reason/checked/total logs, starvation-avoidance rotation for the bounded first 128 independent pair checks, reset/prune of pending verifications, and separate confirmation budget. Plot↔Plot AABB rearm and all original source/callback/target/credit computations remain as before.
4. New `WorldClearanceVerifierTest.java` and one new case in existing `GameImpactCreditTest.java`: exercise >32 cells, pose change and same-grid jitter, new Native contact invalidation, unloaded/colliding World blocks, zero global budget, same-tick repeat, owner generations, World edits during a pending scan, atomic confirmation budget, 8,192 bound, consecutive completed confirmations, gap invalidation, and FSM→ledger issuing a second credit only after two independently proved separation frames.
5. `PhysicalDestroyDeform.java`, `build.gradle`, NeoForge TOML, README: 0.3.1QFix version metadata. No Gradle Wrapper/Actions modifications. No new external dependency. No Minecraft/Sable source or JNI changes.

## Scope and safety constraints

- `WorldClearanceVerifier.Status.CLEAR` is not returned from a multi-tick mixed-time scan alone. The complete current World cell footprint is inspected in one tick before credit rearm. The proof cursor is retained for the next tick's independent atomic confirmation, so two consecutive positive observations can actually reach `ARMED`. A non-CLEAR intervening result resets only the pending separation streak, not Q, issued credits, or owner generations. While `IN_PROGRESS`, `WAIT_ATOMIC_CONFIRM_BUDGET`, `UNAVAILABLE` or `TOO_BROAD`, the FSM does not advance toward `ARMED`.
- Runtime checks only loaded chunks, ensures collision shapes are nonempty, and fails closed if Sable's plot container reports a plot region overlap. The procedure is deliberately conservative: a nonempty collision shape anywhere in the inflated **full AABB** can block rearm even if it does not actually intersect the detailed Plot shape. No unverified geometric inference authorizes damage.
- 8,192 final proof cells is a **hard per-tick global budget**; this version does not solve all arbitrarily large ships. Consider spatially accelerated loaded-chunk/section proof in a separately verified later revision if this limit is hit in logs.
- The original `GameImpactCredit` does not reset a single numeric Q counter. Two verified separations restore `ARMED`; the next independently supported impact creates a fresh `episodeGeneration`. `ContactCreditLedger` uses `(pair, episodeGeneration)` and can issue another Q. Continuous contact never reissues Q.
- All operations are server-thread, read-only. `worldMutation=OFF`; no blocks are damaged, moved, deformed or destroyed.

## Two-session in-game acceptance plan

### Session A — B1 conveyor Plot versus static A1 stone World

1. Use the Actions-built **0.3.1QFix** JAR only, preserving pinned NeoForge 21.1.x, Create 6.0.10, Aeronautics 1.3.2 and Sable 2.0.6. Select B1 Plot whose expanded world AABB spans **at most 8,192 cells**. Avoid any ground/floor World collider within the Plot AABB during the separation hold (airborne placement recommended).
2. Start with B1 separated from every static World collider. Hold still long enough for initial clearance: if the footprint is large this may take multiple ticks per proof. Observe `[PDD-WORLD-CLEARANCE] status=IN_PROGRESS` followed by `status=CLEAR`; twice independently completed clearance observations must bring FSM to `ARMED`.
3. Strike A1, hold contact for ~1 second, slide against A1 without disengaging: only the **first independently authorized impact** may have `APPROVED Q>0`, later identical pair/ticks must show `DUPLICATE_EPISODE Q=0` and `SKIPPED_DUPLICATE` for R2.
4. Move B1 fully away from **all World colliders** (not merely from A1) and hold still ~5 seconds or longer until two separate `CLEAR` results bring `ACTIVE→COOLING→ARMED`. If `BLOCKED`, inspect the collider location; if `TOO_BROAD`, use a smaller Plot for this bounded QFix version; if `WAIT_ATOMIC_CONFIRM_BUDGET`, allow another physics tick without touching.
5. Strike **the same A1 with the same Plot UUID** again. Expected: new `episodeGeneration`, one new `APPROVED` with Q≤64, `PDD-LEDGER status=ISSUED`, sides + unused = issued Q. Repeat once. No special World block creation/shape change needed.

**Pass:** same `PLOT:uuid/WORLD:overworld` pair transitions `ACTIVE→COOLING→ARMED→ACTIVE`, with a new legitimate Q/credit once per verified reimpact; no Q while sliding or blocked. **Fail:** a `CLEAR` occurs while fully touching a collidable World block, or Q reissues during continuous contact. If no `CLEAR` because of `TOO_BROAD`/`BLOCKED`/`UNAVAILABLE`, report as policy limitation or test-geometry blocker, **not** proof that the ledger is broken.

### Session B — B1 versus B2 Plot / load & regression

1. Use two separately assembled Plot UUIDs, collide, hold and rub continuously; check `DUPLICATE_EPISODE`, `r2SkippedDuplicate>0`, no additional ledger issue. Keep original collision callback count/return and world mutation OFF.
2. Fully separate structural Plot AABBs (not merely blocks visibly touching), hold stable for 2+ verified physics observations, then reimpact the same pair. Expect a new Q generation if R2 target and independent approach are verified; no false target credit or native data mutation. Optional create high-point contact to observe `sourceCapSaturated` metadata (100 Native records).

**Required evidence:** full `latest.log` from server start to finish, PDD-DIAG/OBS/NATIVE-TARGET/VERF-FSM/VERF-SEPARATION/WORLD-CLEARANCE/LEDGER/SUMMARY lines, stable Plot UUIDs, and a brief sequence/time of each collision and complete separation. Attach full Actions Build + Callback Contract job logs if compilation/tests fail. The **AI has not performed either game session**.
