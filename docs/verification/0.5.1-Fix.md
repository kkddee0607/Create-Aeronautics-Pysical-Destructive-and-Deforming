# PDD 0.5.1-Fix — integrity/diagnostics release note

Basis: `main` SHA `28a1b1e961b2017090e16ceffe95801d24bcc730`; IDS 1.0.8 §24.4, §35.3.

## Implemented

- Keep original Sable callback, physics, vanilla block mutation, split guard, WAL order, and exactly-once receipt policy.
- Classify Plot break API/readback disagreement without ever promoting an uncertain `PREPARED` receipt to `APPLIED`.
- Log `PDD-PLOT-REREAD` with distinct missing-owner / removed sublevel / epoch / unloaded chunk / block state cases on failure.
- Read existing Sable Java self/merged mass and COM before/after Plot break and at the next `RapierPhysicsPipeline.prePhysicsTicks` HEAD; never modify values or assume native upload.
- One bounded first-active-Plot audit per dimension and 128 outstanding Plot break watches; reset per integrated server shutdown.
- Optional client-only Sable snapshot packet observer to show packed Plot coordinates when Sable reports a missing client sublevel; does not modify packets.
- Keep orphan markers durable and report their recovery without unsafe automatic reassignment.
- Avoid consuming an orphan cleanup queue entry until its journal mutation succeeds.
- Five JUnit cases for readback classification and observer non-authority.

## Diagnostic options

In launcher Java arguments add `-Dpdd.tracePhysicsLifecycle=true` to print **valid** Java mass snapshots as well as anomalies.
Add `-Dpdd.traceSublevelPackets=true` to print missing client-side Plot snapshot positions (first 32 per JVM).
Default: valid mass snapshots are quiet; **invalid** snapshots and readback disagreements are logged.
Native mass/COM upload verification is **UNVERIFIED**, not inferred from Java getters. `sourceCapSaturated` is **NOT** proof of lost native records.

## Release boundary

This patch does **not** modify Sable/SableBridge native libraries, native COM physics, or reassembly/split algorithms. It does not claim to cure the prior Optimizer 1.0 crash: testing without Optimizer is the approved baseline. The missing sublevel packet root cause and PDD/Sable mass-collider lifecycle need actual correlated game evidence; no speculative packet suppression or manual mass rebuild is performed. IDS 1.0.8 §35.3 requires full mass/collider runtime evidence before considering that capability verified.
