# PDD 0.3.0superFix — IDS 1.0.5-A 전체 문서 재감사 (2026-11-01)

## 범위 및 기준

- **작업 목적:** 새 버전 기능 추가가 아닌, 기존 `0.3.0superFix`가 통합설계서 1.0.5-A **전체(§0~§28)** 및 필수 개발 규약을 만족하는지 다시 감사하고 입증 가능한 결함만 수정.
- **GitHub main 기준:** `ed5f206ed06883ce90de85ae847f3211489a31b0` (142 tree entries / 116 blob entries, tree not truncated). 당시 `main`은 이전 `realFix` 계열이며, 이번 비교 대상은 사용자가 첨부한 **superFix 전체 Apply 소스 ZIP**. GitHub 직접 업로드/Actions 실행하지 않음.
- **정본 설계서:** `docs/PDD-1.0.5-Integrated-Design-Specification.md` (SHA-256: `2988945d8552f260897c172350ea33a14baaeebbcd8f7540a44ffbb9fd0b16bb`), 사용자가 제공한 원본과 바이트 동일. §0~§28 포함 1475줄 전체를 버전 규범과 출시 범위를 구분해 검토.
- **개발 범위:** §14.1~14.3, §15.1, §20~§23, §26의 0.3.0 기능 게이트. §7~§10 및 §24~§25는 0.4.0 이후 또는 DVT를 위한 사전 계약으로 검토했으며, **0.3.0에서 월드 변경·가짜 물성·변형·응력 구현을 켜지 않음**.

## 재감사 변경 — 증거가 확인된 것만 수정

1. `collision/SableConsumerTargets.java`: 이전 R2는 Plot/World 한쪽 후보를 실제 블록과 대조하기 전에 **같은 native 레코드의 양측 사후 효과 접촉점이 동일 world frame을 가리키는지** 확인하지 않았다. `corroboratedContact()`를 추가하여 미일치·프레임 누락·회전 불일치를 `CONTACT_FRAME_UNCORROBORATED`로 거절. `R2_CORROBORATED_GAME_PROXY`는 **동일 효과 소비 경로에서 교차 확인된 게임 타깃 후보**의 출처 표시이며, **ColliderPose 또는 solver manifold의 정밀 증명/`SOLVER_NATIVE_VERIFIED`가 아니다**. §0.5, §5.3~5.5, §21.1~21.4 준수.
2. `collision/RealFixRuntimeBridge.java`: Plot↔World의 사전 분리 기록에서 `Pair.canonical()`의 정렬된 소유자 A/B와 전달한 `Box` A/B의 순서가 다를 수 있었다. `alignBounds()`로 canonical owner 기준으로 보정해 재접촉 이력과 `approaching()`의 A/B 해석 불일치 수정. R2 실제 성공 수와 R3 성공 수를 별도 카운트. 양측 모두 미검증일 때 `quality=SOURCE_UNVERIFIED`로 로깅하여 허위 승격 차단. §6, §21~§23.
3. `collision/GameImpactDispatch.java`: 휴면 진단 출력에 남아 있던 `version=0.3.0realFix`를 `0.3.0superFix`로 수정. 예산 알고리즘 자체는 변경하지 않음.
4. `src/test/.../SableConsumerTargetsTest.java` 및 `SuperFixNativeImpactTest.java`: 양측 세계접점 일치/불일치, 90° 회전, canonical bounds 정렬, 수치 좌표 동일해도 Plot/World 타깃 구분 테스트 추가. 기존 JUnit 파일 삭제/비활성화하지 않음.

### 미해결·출시 판정 한계

**특히 중요한 제한:** 두 effect-point가 world-frame에서 일치해도 native collider의 전체 relative pose가 공개됐다는 의미가 아니다. 따라서 `R2_CORROBORATED_GAME_PROXY`는 실험적으로 의미 있는 후보이며 정밀 solver contact 계약은 **미승격**. 실제 회전 기구·World(-1) collider에서 성공률은 테스트 로그로만 확인할 수 있다. `TARGET_UNVERIFIED`, `CONTACT_FRAME_UNCORROBORATED`, `INITIAL_CONTACT_UNKNOWN`, `APPROACH_UNVERIFIED` 등에서는 절대로 Q를 강제하지 않는다. 이번 변경은 false positive를 줄일 수 있지만, 효과 레코드 기하가 불충분한 환경에서는 실제 타격도 더 보수적으로 거절할 수 있다.

## 인게임 테스트 (최대 2세션)

**사전 조건:** GitHub `incoming/`에 이 ZIP **1개만** 업로드 → 사용자가 Apply action 실행 → Build 및 Callback Contract Test 통과한 JAR 설치. 이전 PDD 버전 JAR 중복 설치 금지. Java 21, MC 1.21.1, NeoForge 21.1.x, Sable 2.0.6, Create 6.0.10, Aeronautics 1.3.2. 사용자 JVM 인수의 이전 `pdd.proxy.*`, `pdd.moreRog`를 추가하지 않음. world mutation OFF.

**세션 A — Plot↔World:** 작은 Plot의 석재 한 면을 정적 돌벽과 분리한 상태로 2틱 이상 유지한 뒤 타격, 지속 정지/접선 이동 20틱, 확실한 재분리 2틱 후 재타격. `PDD-NATIVE-TARGET`의 R2/R3 / 실패 코드, `PDD-TARGET`의 별개 Plot 상대좌표·정적 World 좌표, `PDD-EPISODE`의 `previousSeparated`, `APPROVED`/`Q`/`DUPLICATE_EPISODE`, callback count를 확인. 인게임 ground truth의 실제 블록과 타깃 키가 일치하고, 증명된 타격에 단일 Q, 정지 중 Q=0, 변형/파괴 없음이 합격. 불일치면 FAIL `G-TARGET`/`G-LEDGER`.

**세션 B — Plot↔Plot:** 서로 다른 Plot UUID 한쪽 90° 회전, 원통/계단/다중 후보 접촉, 분리 후 재충돌, 20틱 정지. 두 owner ID와 각자의 center-relative block, 후보 cap 8, target ambiguous면 Q=0, 한 번만 Q, 원본 Sable 충돌/반발 정상, 분리 직후 정상 rearm을 확인. false `VERIFIED`, 크래시 또는 물리 반응 달라지면 FAIL.

**오류 제출:** 두 세션의 `latest.log` 전체, GitHub Build/Callback 로그(실패 시), PDD 장면 시각/차원/블록 좌표/Plot UUID 가능 시, `[PDD-OBS]`, `[PDD-NATIVE-TARGET]`, `[PDD-TARGET]`, `[PDD-EPISODE]`, `[PDD-SUPERFIX]`, `Exception` 최초 원인. 무증거 피해를 승인하는 임의 완화는 금지.
