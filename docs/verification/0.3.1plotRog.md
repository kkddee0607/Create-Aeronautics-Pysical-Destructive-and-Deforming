## Source-to-contract findings applied

1. Sable Rust `dispatcher.rs` converts each voxel cuboid contact from per-block local into LevelCollider/Body local by adding `blockCenter - centerOfMass`. Its `event_handler.rs` forwards *two independent* `local_p1/local_p2` witness points. **No source contract says their world positions coincide.** Consequently `frameResidual().distance>0.25` is not a valid global R2 reject predicate.
2. Sable Java `RapierPhysicsPipeline.processCollisionEffects` uses `raw+logicalPose.rotationPoint` as the Plot allocated-grid point and `raw` directly on the static world side. `OwnerResolver` maps Plot allocated-grid positions through `getCenterBlock()` to embedded coordinates and validates loaded live blocks and collision shapes.
3. The Sable physics system runs one or more substeps, updating poses between them; effects are drained only after all substeps. Reprojecting a witness via the *last* effect-phase pose cannot prove the other body's contact-time position. This is why R3 is **disabled as a Q authority** until a same-substep snapshot can be paired to each native record.
4. Sable `MergedMassTracker.uploadData` can change `rotationPoint` with the COM. `NativeContactMassEpoch` checks the stable COM and identity across **every observed pre-substep** and checks against the effect-frame COM. A missing substep body or unstable origin masks only that Plot side. This is conservative; COM epoch remains a game-runtime hypothesis until played.
5. Rust `clearCollisions` truncates to at most 100 records. Exactly 100 observed records are counted as *cap-saturated polls*, **not** proven missing native records.

## In-game acceptance: no more than two test sessions

**Prerequisites:** User applies ZIP via GitHub's existing Apply workflow, runs existing Build and Callback Contract Actions, and places **only the newly built 0.3.1plotRog JAR** (not the ZIP or an old PDD JAR) in the 1.21.1 NeoForge `mods/`. Run with Sable 2.0.6, Create 6.0.10, Create Aeronautics 1.3.2 and the same physical setup as prior tests; set `-Dpdd.verf.enabled=true` (default). Keep `worldMutation=OFF`. Open `latest.log` from world start.

**Session 1: Plot against World (B1→A1 stone wall; B1→A2 grass).** Start with B1 clearly separated, strike, hold in continuous contact, separate for ≥2 stable physics observations, strike again. Repeat with a different edge/corner, if practical. Expected evidence: native `PDD-OBS`, `PDD-NATIVE-TARGET`, and verified R2 Plot/World targets; `PDD-EPISODE`, `PDD-LEDGER` emit at most one Q reservation per correctly armed distinct episode; Q share A+B+unused equals issued Q. A `PDD-PLOTROG-WITNESS` distance >0.25 must *not* by itself suppress both owner-local shape audits. If static Shape missing, expect explicit unverified side, not a fabricated hit.

**Session 2: Plot against Plot (B1→B2 balloon; B1→B3 stone Plot).** Repeat impact, held contact, actual separation and re-impact. Include movement/rotation and multi-voxel contact. Verify both Plot UUIDs remain distinct, their local targets really correspond to the seen blocks, valid target sides share the same Q; `TARGET_LIMIT_A/B` quarantines a side with >4 real blocks, no arbitrary four-block subset. If COM changes or frames are incomplete, expect `PDD-PLOTROG-EPOCH` and Q=0 for that affected side; the independent valid side may remain `PARTIAL`. No R3 cross-substep Q or R4 inferred Q.

**Success:** Correct owner and block identity for R2 targets; genuine valid separated witness contacts no longer denied purely due 0.25 world distance; no Q issued twice per episode; Q sum conserved; no mutation, crash or native/callback contract change; no unchecked chunk loads. Fewer `NO_VERIFIED_REGION` due solely to world witness separation, but some failures can remain for actual absent/ambiguous shapes and epochs.

**Failure evidence to return:** Full `latest.log` containing `PDD-DIAG`, `PDD-OBS`, `PDD-PLOTROG-WITNESS`, `PDD-PLOTROG-EPOCH`, `PDD-VERF-REGION`, `PDD-VERF-FSM`, `PDD-NATIVE-TARGET`, `PDD-EPISODE`, `PDD-LEDGER`; relevant Actions full failed job log; test scene B1/A1/A2/B2/B3, exact visually contacted block, server configuration and loaded mod list. ## Remaining uncertainties

- No proof that all source contacts correspond to a particular substep or that native Rapier penetration `dist` can be reconstructed from the 15-double payload. `PDD-PLOTROG-WITNESS` transverse/normal metrics are effect-phase diagnostics only.
- R2 source point exactness near voxel junctions depends on the pre-existing bounded `1/32` tolerance and actual voxel shape; 3D game verification is still required.
- R3 credit remains unavailable pending a real per-contact same-substep pose. Do not restore it by increasing the 0.25 distance tolerance.
- The official Gradle compile and tests, version compatibility and game acceptance remain for the user to verify in GitHub Actions/in-game.
