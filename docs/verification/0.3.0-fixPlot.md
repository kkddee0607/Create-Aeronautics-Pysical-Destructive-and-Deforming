## Algorithm and trust boundaries

- `SableFrameCapture` stores pre-solver snapshots by `dimension + gameTime`; each body records `getRuntimeId()`, stable Plot UUID, immutable pose/mass/velocity. The original callback stays original; no mutations.
- A read-only `RapierCollisionTelemetryMixin` sees the original 15-double array and tags it with the `RapierPhysicsPipeline.level` dimension/game time. The returned array is **unchanged**. Invalid integer IDs/nonfinite payload, malformed arrays or dropped records prevent using untrustworthy evidence.
- `NativePlotDirection.prepare` only considers dynamic/dynamic native body IDs. Both IDs must correspond to actual uniquely identified Plot bodies in **every** pre-solver snapshot of the same dimension/tick. The two local collider normals are transformed separately into world frame, must oppose with cosine >=0.98 and agree with all other contact normals/frames with cosine >=0.98. Different native body ordering is canonicalized.
- `NativePlotDirection.evaluate` additionally verifies both live Plot target keys, exact stored pair runtime IDs, and target-local block coordinates from `G-COL-02`. For **every** pre-solver snapshot in that tick, check positive *signed* projected translational approach and a rotational dominance bound at each target voxel. If any snapshot rejects, result rejects. Successful samples use the **minimum** proxy budget in that tick and the user-configured `P-16` factor/step cap. This is a **tick-wide conservative game proxy**, not an `EXACT_CONTACT` or an exact native impulse. No center-to-center normal, precise contact point, force scalar, unknown JAR data or post-solver velocity substitutes.
- The 0.3.0 `ImpactEpisodeLedger` / `ImpactContinuityGate` prevents repeated credit for the same owner-pair in one ongoing contact. Multiple target blocks are still recorded; no downstream damage mutations occur. Source logging distinguishes `NATIVE_PLOT_PAIR_...` from `BLOCK_FACE_ESTIMATE`.
- Missing native record, filtered contacts, conflicting normals, missing any pre-solver snapshot, rotation-dominated hit, closed or unconfigured P-16 all yield zero and a reason. The **native effect scalar is only diagnostic**. A world block's collision face policy is unchanged from 0.3.0 FIX.

**Explicit residual risk:** Post-solver native effect samples are thresholded and tick-aggregated. The strict *all pre-substeps* test is a conservative acceptance condition, not precise causality of a specific native manifold at a specific substep. It may reject true impacts (especially rebounds, corner contacts and significant rotational motion). The native pair's normal is a **body-pair** source; 0.3.0 does not prove that any particular callback block received that native manifold's impulse. The exact rotation model remains tested with independent inputs and its final live integration stays at milestone 0.9.1. If no Plot–Plot `APPROVED` events appear even with a level, head-on full-cube test and native pair records, classify `G-MATH-01` Plot–Plot as *in-game not passed* and fix from the rejected evidence instead of treating it as success.

## In-game verification: at most two sessions

1. **Session A — reproducible proxy + original regression**. JVM args `-Dpdd.proxy.enabled=true -Dpdd.proxy.factor=0.5 -Dpdd.proxy.stepCap=100 -Dpdd.debugCollisions=true`. Make two separate *full-stone-cube-faced* Sable physical structures (do not replace Sable/NeoForge versions), each with its own stable Plot ID. First move structure A directly into stationary B with negligible rotation; repeat moving B into stationary A, then a tangential slide or outward separation. Also repeat the old static stone wall and grass-floor collisions to confirm existing World–Plot `BLOCK_FACE_ESTIMATE`. Expected: `phase=NATIVE_PLOT_BRIDGE ... acceptedPairsTotal>0` when source effects exist (check `pairRejections` and `nativeContacts`), `phase=APPROVED ... source=NATIVE_PLOT_PAIR_OPPOSING_NORMAL_ALL_PRE_SUBSTEPS_MIN_GAME_PROXY ... normalBtoA=<non-null> ... budget>0` on an unambiguous approaching Plot–Plot pair. Unknown/missing source must log `DIRECTION_UNVERIFIED` and never invent approval. `APPROVED` must never be labelled `EXACT_CONTACT`, and `worldMutation=OFF` throughout. A missing Plot–Plot approval after confirmed source events is a **failure to demonstrate the live positive path**.
2. **Session B — user's mixed balloon/wall regression**. Reuse the balloon with envelope, adjustable burner, rope connector, levitite, reinforced-deepslate weight and bottom chain. Shake against the static stone wall/grass floor, then collide it with the separately assembled physical stone wall in both motion directions. Try rotated, glancing and resting contacts. Expected: Plot and World `TargetKey` verify with `targetUnresolved=0`, native normals when available and compatible; `ROTATION_UNRESOLVED` or `DIRECTION_UNVERIFIED` (not false positive budgets) for arbitrary rotation/corner contacts. `DUPLICATE_EPISODE` should prevent repeated damage credit while resting. Include a genuine Belt/Fragile original-callback action if testing its return-path preservation; merely seeing `original=0` is not proof. Fatal exception, new collision mutation, positive credit for separation/resting, or unexpected callback result change FAILS the gate.

Both sessions must record `[PDD-G-MATH-01] POLICY`, `phase=NATIVE_PLOT_BRIDGE`, `phase=SUMMARY`, `phase=APPROVED` samples, `G-COL-01/02`, and `PDD-COLLISION` malformed/dropped counts, and report the JVM args. Do not regard the absence of warnings as proof of game physics accuracy.
