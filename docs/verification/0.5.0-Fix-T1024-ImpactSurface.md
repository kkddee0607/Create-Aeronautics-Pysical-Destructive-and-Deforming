## Delivered behavior

1. `MaterialProperties.threshold` and all CSV T parsers accept integer 1..1024, including the previously rejected **four-digit** literal 1024; H stays 0..255, D/E stay 0..100.
2. Bundled default block catalog replaced by the supplied T1024 material sheet (`pdd/materials/blocks.csv`, 1844 rows). Bundled item catalog replaced by supplied current item sheet (`pdd/materials/items.csv`, 2159 rows). Existing user file-overrides and metadata precedence preserved.
3. World accumulated integer damage supports 0..1024, remainder/deformation/crack remain byte-range. Internal fixed-point scale remains 256, with increased saturation. `pack24()` remains a **legacy-only** 0..255 form and rejects wider values instead of truncating.
4. `SparseStateCodec` production schema 2 writes unsigned two-byte damage; legacy schema 1 U8 remains readable. The PDD `WorldPersistentJournal` disk schema 2 similarly writes two-byte damage, loads schema 1 manifests/shards/WAL and upgrades via write/fsync/atomic checkpoint manifest; original legacy 0.4.1 schema 2 WAL migration is retained. The save directory name `pdd-world-0.5.0` is **unchanged** for migration.
5. `GameImpactCredit` retains one credit per proven collision episode; independently verified moving regions may mint another episode after two quiet native-force frames, a force rising edge and new contact region, while requiring pre-solver native closing velocity evidence. A previous uncredited active pair receives a *rate-limited* R2 re-audit; large F alone can **never** bypass authorization. The normal equality/owner/source checks remain enforced.
6. `ContactFacePatch` accepts bounded noisy near-axis solver corner normals as belonging to the same witnessed face, then checks **every reconstructed target** against actual owner collision shapes before adding it. `ContactCreditLedger` distributes the **single existing group F and Q budgets** over independently verified targets; no per-corner Q multiplication.
7. `[PDD-HIGH-F]` and `[PDD-IMPACT-DECISION]` log the high-force authorization rejection/approval cause, independent native approach, region movement and quiet-force qualification; `[PDD-CONTACT-PATCH]` reports face candidates, checks, accepted targets. `[PDD-PERSIST]` and `[PDD-COMMIT]` continue recording durable world results.

### Important limitations (not proven completed)

- With only one isolated native contact witness and no source-corroborated polygon, contact-surface reconstruction is limited to the old bounded local shape-checked halo. **This is not a guarantee that every cell on an arbitrarily large physical face is discovered.** Fully reliable single-witness, whole-collider surface reconstruction requires both collider shapes or separately verified source geometry and broad-phase collision checks; manufacturing contacts across the whole AABB was intentionally rejected.
- Reimpact of the **same** still-contacting region without a proven distinct region and new pre-solver inward motion remains uncredited to prevent a stationary solver reaction force from repeatedly destroying blocks. The observed large-force no-break symptom may therefore still occur in such configurations.
- The revised face patches are geometric *Game damage targets*, not extra Sable native contact records. No new Sable physics, callback, impulse or velocity is synthesized.
- World damage/destruction only: Plot actual destructive commit remains reserved for 0.5.1; Plot-side impact damage planning remains observation/previews.

## Two-session in-game validation (expected outputs, not a claim of real success)

### Session 1 — credit/face and durable threshold

1. **Back up the entire test world**, particularly `data/pdd-world-0.4.1.wal` and `data/pdd-world-0.5.0/`. Keep Sable 2.0.6, Create 6.0.10, Aeronautics 1.3.2 and NeoForge 21.1.x. Do not delete previous persistence files.
2. Apply the full ZIP; run GitHub `PDD Manual Build` and `PDD Callback Contract Test`, install resulting 0.5.0-Fix jar.
3. Set JVM arg `-Dpdd.persistence.verbose=true`; collision diagnostics are also enabled by `-Dpdd.verf.enabled=true` if supported by the running source (`RealFixRuntimeBridge` uses the existing `pdd.verf.enabled` flag). On resource-limited Android reduce other debug mods if necessary.
4. In a backed-up world, accelerate a verified flat, broad 5×5 or larger Plot face into loaded World blocks from **a positively separated state**. Test another collision after a demonstrated separation and another moving, newly contacted region in continuous contact. Do **not** treat constant compression/resting force as a new collision.
5. Compare `[PDD-OBS]` → `[PDD-R2-PERF]`/`[PDD-CONTACT-PATCH]` → `[PDD-IMPACT-DECISION]`/`[PDD-EPISODE]` → `[PDD-Q-SEAL]`/`[PDD-F-LEDGER]` → `[PDD-COMMIT]` and `[PDD-PERSIST]`. For each collision capture `nativeTick`, owner pair, force, `credited`, credited reason, face candidate/verified counts, issued Q and actual block damage/destruction. One large face must not issue Q once per corner.
6. Place sample blocks with CSV T >255, apply repeated accepted impacts and confirm accumulated damage can **exceed 255** and eventually meet T if sufficient budget; check `damageU16`, `remainderU8`, `schema=2` and actual break. Lack of break is not necessarily a failure unless impact Credit, allocated F and committed damage establish a sufficient threshold crossing.
7. Exit normally. Confirm `[PDD-PERSIST]` checkpoint/summary with no storage faults and retain `latest.log`.

### Session 2 — recovery and replacement

1. Restart *the same world*; confirm schema 2 restoration rather than fresh data, with nonzero damage/receipts and no unexpected `fault`/`HALTED`.
2. On a non-broken partially damaged block, verify damage continuity. Mine/replace the same block ID and repeat a collision. A previous ApplyId must never be accepted as a new destructive intent; the newly placed block must not inherit earlier damage.
3. Repeat the flat-face and independent region reimpact test, check separate results for Credit rejections vs shape rejection vs World CAS/protection or storage rejection. Save logs and stop.

**Success criteria:** no startup crash, all block/item material rows load without T1024 parser errors, schema migration/restore and checkpoint finish, nonzero broad-face *verified* candidates where sufficient source witnesses exist, one F/Q budget per event, independently authorized impacts produce durable World damage and any authorized threshold crossing may break Vanilla blocks once. Any high-F `DUPLICATE_EPISODE` should be evaluated together with `nativeApproach`, `quietForceFrames` and `regionMoved` before calling it an error.

**Required logs if failed:** both full `latest.log`, `debug.log` (if enabled), `[PDD-*]` around event time including policy and FPS/lag warnings, full GitHub Actions `compileJava`, `compileTestJava` and JUnit error text, exact mod JAR versions, and if a storage failure occurs a backed-up copy of the relevant PDD world storage directory (do not manually edit it). Reproduction shape and movement direction are important for surface bugs.
