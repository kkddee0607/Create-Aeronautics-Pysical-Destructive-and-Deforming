### Safety details of the per-event cache

`OwnerResolver.propagationSnapshot` lives only during **one synchronous server-thread approved credit**; caches keys `(owner,x,y,z)`, separately for WORLD and PLOT. First access runs existing chunk/owner/shape/fingerprint `check`, prevents world fallback within Sable plot storage and uses stable Plot-center mapping. A missing owner, invalid owner mapping, unloaded chunk, unavailable collision shape or coordinate overflow returns UNKNOWN, **not a proved terminal**. No cross-tick or cross-collision cache is retained; no asynchronous level access; no chunk is loaded for traversal. Caching cannot turn an unverified target into an eligible block or mint extra Q.

## 5. Two in-game sessions and acceptance criteria

### Session A — correctness / geometry / native cap

**Setup:** Minecraft JE 1.21.1 / NeoForge / installed matching external mods; 0.4.0finalFix JAR *only*, no older PDD JAR. Use a **stone sphere with radius ≈3.5**, multiple contact faces and a central slime block at Plot local `(0,0,0)`, and at least one 3-block serial/diagonal test. The initial Plot should be airborne before contact so that an independently observed separation/approach authorizes a fresh one-credit event. Enable the three detail options above **only for this short recording**.

**Procedure:** (1) Start the game, verify `[PDD-POLICY]`, and note the Plot UUID. (2) Strike the ground once at an angle, then separate the Plot fully and strike a different face; include a contact producing 100 native effect records if possible. (3) Stop after capture and provide `latest.log` **including start and end**, not only PDD lines.

**Required evidence:** the same event has one approved credit and no duplicate credit on sustained contact; `PDD-NATIVE-NORMAL` verifies owner-local mean with `records>0`, and if `nativeCapSampled=true` its reason ends `_NATIVE_100_CAP_SAMPLED`. `PDD-DIRECTION` reports valid `fVectorStatus=CORROBORATED` **even if** `gridAxisStatus=NONAXIAL_OR_UNVERIFIED`, because an oblique vector is legitimate F evidence. If true opposing contact normals cancel or frame/owner proof is invalid, report explicit UNKNOWN and do not invent a direction. `PDD-F-INVARIANT` must report `FStatus=PASS QStatus=PASS`; all child receipts and F edge sums equal parent payments; same child processed once; slime `(0,0,0)` must be a genuinely processed Plot node if the trajectory crosses it. Any safety cap/unloaded boundary must be explained as `unresolvedF`, not silently added to last-block Q. `worldMutation=OFF` is expected.

### Session B — performance on identical geometry

**Setup:** same world/Plot and mod list, no other config change except disable full trace: `-Dpdd.f.trace.enabled=false` (default); keep stage summaries. Prefer actual dedicated Linux server if available; otherwise mobile data are comparative only.

**Procedure:** repeat the same sphere impacts 5–10 times, with adequate separation for new credit between hits; separately run a short larger Plot contact test. Preserve the full log and, if available, server TPS/MSPT data.

**Required evidence:** `PDD-R2-PERF`, `PDD-NORMAL-PERF`, `PDD-F-PERF`, `PDD-MATERIAL-PERF` show each stage's measured nanoseconds; none of the F/Q invariants or target material values regress; no frame mismatch, unrelated owner Q, duplicate accepted credits or unexpected exceptions. Compare the median/P95 stage timings and 50ms full-tick budget to the previous duperFix scenario. A large reduction is *expected*, but neither a numerical speed-up nor sustainable 20 TPS is declared without this real run. If `planNanos` still frequently exceeds the target server tick budget, this release **must not** be declared server-performance validated.
